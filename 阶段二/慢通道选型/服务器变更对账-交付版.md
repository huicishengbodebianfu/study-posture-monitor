## 一、现行架构（骨架）

```
ESP32-S3-CAM ──POST /detect──▶ ① 方向自适应（倒装自动转 180°，进程级记忆）
                                  │
                                  ▼
                            ② 快速通道（本地 YOLOv8n-pose + OpenVINO，~100ms）
                               head_height / shoulder_level → 端正/不端正/无法判定
                                  │
                    ┌─────────────┴──────────────┐
                    │                            │
          ③ 慢通道（异步，30s 一次）      ④ 融合 fuse()
           15 个后端 / 11 个账号            优先级见 §1.3
           并行 3 路、quorum 2、早停        │
                    └──────────────┬─────────────┘
                                   ▼
                          ⑤ 规则引擎（连续 2 帧 + 60s 去重）
                                   ▼
                          应答（含 OLED 字段）
```

### 1.1 快速通道

```
shoulder_width = |ls_x − rs_x|
head_height    = ((ls_y + rs_y)/2 − nose_y) / shoulder_width
shoulder_level = |ls_y − rs_y| / shoulder_width

head_height < 0.28      → 不端正
shoulder_level > 0.45   → 不端正（仅拦极端侧歪，实测无区分度）
关键点不可靠/几何崩坏   → None（无法判定）
```

阈值来源：真机 120 帧标定（端正最低 0.493、趴下最高 0.080）。

### 1.2 慢通道

| 项 | 值 |
|---|---|
| 后端 / 账号 | 15 个 / 11 个 |
| 并发 | 3 路，quorum 2，deadline 15s，错峰 150ms |
| 早停 | 达成 quorum 后等 150ms 收尾 |
| 熔断 | 连续 3 次失败 → 120s；401/403/404 立即跳闸 |
| 缓存 | TTL 45s |
| 配额 | 按账号记账，落盘，重启不清零 |

### 1.3 融合优先级（命中即返回）

| 序 | 条件 | 结果 |
|---|---|---|
| 1 | 慢通道 upright + conf≥0.9 + 同场景 | 端正（`slow_override`） |
| 2 | 快通道不端正 | 不端正 |
| 3 | 快通道端正 + 慢通道语义不端正（phone/daze）+ 同场景 | 不端正（`slow_semantic`） |
| 4 | 快通道端正 | 端正 |
| 5 | 慢通道不端正（姿态类）+ 该提醒 + 同场景 | 不端正 |
| 6 | 慢通道不端正但"不该提醒" + 同场景 | 无法判定 |
| 7 | 慢通道端正 + 同场景 | 端正 |
| 8 | 其余 | 无法判定 |

## 三、四轮对账（P0 / P1 / P2 / P3）

### 3.1 P0 —— 达成 quorum 立即返回

**问题**：`wait(futs, timeout=deadline)` 只在"全部完成或超时"返回。
两票 5 秒就一致，仍要陪跑第三路到 12~15 秒。实测中位 11.95s。

**改动**（`resilience.py` → `_analyze_parallel`）：

```python
while pending:
    done, pending = wait(pending, timeout=min(0.4, left),
                         return_when=FIRST_COMPLETED)
    ...
    if self._quorum_reached(valid_now):
        grace_until = time.time() + self.quorum_grace   # 0.15s 收尾
```

新增 `_quorum_reached()`：按 `upright` 分组，任一组达 quorum 即算够票。

**效果**：中位延迟 **11.95s → 6.58s（-45%）**。

**测试**：
- `test_p0p1p2.py`：早停桩测试 0.45s 返回（第三路需 5s）
- 线上 5 轮：5.75 / 7.61 / 4.55 / 9.73 / 6.58

**风险**：第三票可能推翻两票一致——但 quorum=2 本就是定义好的可信标准。

---

### 3.2 P1 —— 账号标识改为 "域名 + key 指纹"

**问题**：`seen` 只按 `base_url` 去重，把 9 个独立账号压成 5 个用。

**改动**（`resilience.py`）：

```python
@staticmethod
def account_of(be) -> str:
    if be.account:                      # 支持 AI_FALLBACK{n}_ACCOUNT 显式指定
        return be.account
    host = 主机名
    return f"{host}::{sha1(api_key)[:6]}"
```

选路 `seen` 从 `base_url` 改为 `account_of(be)`。

**效果**：有效账号 **5 → 11**。

**测试**：`test_p0p1p2.py` 断言同域名不同 key 得到不同账号、不同域名不同账号、显式 account 优先。

**注意**：必须与 P2 同时上。同域名多 key 共享 IP 限流，只做 P1 反而更容易 429。

**问题**：完全无计数。OpenRouter 免费 50 次/天，按每 30 秒一轮的节奏约 25 分钟烧完。

**改动**（`resilience.py` 新增 `QuotaLedger`）：

| 能力 | 说明 |

| 双维度 | `daily` + `rpm`（每分钟） |

| 选路过滤 | 超额账号直接跳过，不浪费必然 429 的调用 |
| 观测 | `GET /pool` 的 `quota` 字段 |

```

```

**测试**：`test_p0p1p2.py` 覆盖每日上限、持久化重载、rpm 限流、快照剩余额度。

### 3.4 P3 —— primary 软降级

**问题**：primary 无条件占一个名额，且启动测速跳过它，EWMA 恒为 0，慢了也看不出来。

**关键坑**：启动探测是 `1x1 图 + max_tokens=8`，真实调用是 `638 字符提示词 + 真图 + 800 tokens`，
两者差 2~3 倍。直接比较会把质量基线误降级（实测 primary 探测 2.05s vs fallback2 0.36s，**5.7 倍**）。

**改动**：

```python
# Backend 新增，只由真实调用更新
real_ewma: float = 0.0
real_samples: int = 0

# 启动探测传 real=False，只进 latency_ewma
```

软降级四条同时满足：

```
① primary_demote_ratio > 0
② primary.real_samples ≥ 2
③ 至少 2 个备用 real_samples ≥ 2
④ primary.real_ewma > 最快备用 real_ewma × ratio(1.6)
```

**软**的含义：只取消保送名额，primary 仍进候选池按速度竞争，
所以它继续被调用、EWMA 持续更新，不会僵死。

**效果**：线上触发 2 次降级（primary 6.49s vs 最快备用 3.22~3.41s），
随后 primary 回落到 6.17s、最快备用 4.40s（比值 1.40）自动停止，无横跳。

**测试**：`test_p3.py` 10 条，含"备用只有探测值→不降级"、
"降级后实际调用 `[f1,f2,f3]` 不含 primary"、"不降级时 primary 排第一"。

## 八、自检脚本发现的两个 bug（2026-11-09）

`verify_server.py` 首次运行就抓出 2 个此前测试没覆盖到的问题，都已修复。

### 8.1 Bug A：语义类翻案缺同场景校验

- **现象**：端正图被判 `SL`（低头）
- **根因**：融合里"快通道端正 + 慢通道语义不端正（phone/daze）"这条分支
  只校验了状态类别，**没校验同场景**，于是把别的帧的判定套到了当前帧
- **修复**（`multimodal.py`）：

```python
if (slow is not None and slow.upright is False and slow.should_alert
        and slow.state not in POSTURAL_STATES
        and self._same_scene(slow.frame_key, frame_key)):   # ← 新增
```

### 8.2 Bug B：方向提示被锁死 + `_raw_hh` 静默失效（连环）

两个独立缺陷叠加，表现是"倒置真机帧正常，但正立网图被判低头"：

**B-1 方向提示锁死**

旧实现里，两个方向都检不到人时（空教室、黑帧）会把 `_flip_hint` 锁成 `False`，
此后所有倒置的真机帧都被按正向处理，`head_height` 变成 −0.32。

**B-2 `_raw_hh` 一直返回 None**

新加的"几何合理性检查"用了 `NOSE / L_SHOULDER / R_SHOULDER` 三个常量，
但它们没在 `app.py` 里导入 → 触发 `NameError` → 被宽 `except Exception` 静默吞掉 →
检查永远不触发。

**修复**：

```python
# 1) 导入常量，收窄异常
from posture import (NOSE, L_SHOULDER, R_SHOULDER, Thresholds, RuleEngine, ...)
except (TypeError, IndexError, ValueError):   # 不再吞 NameError

# 2) 方向判断改为"检测 + 几何"双依据，且支持双向自愈
_suspicious = keypoints is None or (_hh is not None and _hh < RETRY_HH)   # RETRY_HH=-0.25
if _suspicious:
    alt_rot = not cur_rot
    ... 若另一方向几何更合理则切换并记住 ...
elif keypoints is not None:
    _flip_hint = used_flip
# 两个方向都认不到人 → 不改变提示
```

`RETRY_HH=-0.25` 的取值依据：趴桌实测只到 −0.10，而倒置的端正帧到 −0.32，两者不重叠。

**验证**（混合方向序列）：

```
倒置真机帧 frame-0001  → hh= 0.5091  UP
倒置真机帧 frame-0002  → hh=-0.1035  SL   （正确判为趴桌，未误触发翻转）
正立网图  w_upright_lib → hh= 0.3352  UP   （自动切回正向）
空教室                 → AWAY
倒置真机帧 frame-0002  → hh= 0.5231  UP   （自动切回翻转）
```

### 8.3 顺带修正自检脚本

- 趴下组的 `blow` 次数受"连续 2 帧 + 60s 去重"的瞬时状态影响，快速连发时会抖动，
  改为 **WARN**（`True/False/None` 三项口径仍必须与基准一致）
- "端正组零误吹"保留为 FAIL 级硬指标
