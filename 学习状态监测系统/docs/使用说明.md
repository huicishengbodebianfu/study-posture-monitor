## 2. 物料与接线

### 2.1 物料清单

| 类别 | 物料 | 备注 |
|---|---|---|
| 主控 | AI Thinker ESP32-CAM | **必须带 PSRAM** |
| 下载器 | USB-TTL（CH340 / CP2102） | 烧录 + 供电 |
| 执行 | 5V 无刷涡轮鼓风机（≤0.3A，2 线） | 吹手提醒 |
| 开关 | S8050（NPN，TO-92） | 不能用 PNP 的 S8550 |
| 保护 | 1N5819 肖特基 | 三极管方案**必接** |
| 指示 | 5mm 红色 LED + 220Ω | |
| 电阻 | 220Ω（基极限流）、10kΩ（下拉） | |
| 电容 | 100nF（风扇旁）+ 470~1000µF（5V 母线） | 防复位 |
| 电池（可选） | 18650 带保护板 + TP4056(1A) + XL3608-5V | 便携使用 |

### 2.2 引脚（以本表为准）

| 功能 | GPIO | 接法 |
|---|---|---|
| 风扇 PWM | **13** | GPIO13 → 220Ω → S8050 基极(B)；B 再经 10kΩ 下拉到 GND |
| 红色 LED | **14** | GPIO14 → 220Ω → LED 长脚；LED 短脚 → GND |
| 摄像头 | 固定 | 由 `esp32-camera` 库管理，不用手动接 |
| 免打扰按钮 | — | **当前禁用**（`BUTTON_ENABLED=0`），无需接 |

**S8050 接线（低边开关）**

```
5V ────────────── 风扇红线(+)
                    │
              1N5819（带环端→5V，反向并联）
                    │
风扇黑线(−) ── S8050 集电极(C)
S8050 发射极(E) ── GND
S8050 基极(B) ── 220Ω ── GPIO13
                  └─ 10kΩ ── GND   ← 上电钳位，风扇不转
```

> ⚠️ 1N5819 方向接反 = 一开风扇就短路。焊接前用万用表确认。
> ⚠️ 完整图示与替代方案见 [接线图.md](接线图.md)（其中按钮章节已失效）。

### 2.3 供电

**调试**：USB-TTL 的 5V 直接供 ESP32-CAM，先跑通再上电池。

**便携**：

```
18650 ─▶ TP4056(带保护板) ─▶ XL3608-5V ─▶ 5V 母线 ─▶ ESP32-CAM / 风扇
                                          └─ 470~1000µF 电容到 GND
```

> 风扇启动瞬间电流大，没有大电容会拉低 5V 导致 ESP32 复位。
> 端子对照表见 [接线图.md](接线图.md) §5.2。

## 3. 云端服务

### 3.1 检查现有服务是否正常

```powershell
# 健康检查
curl.exe http://YOUR_SERVER_IP:8000/health
# 期望：{"status":"ok"}
```

```powershell
# 用一张测试照片测判定（自备一张 JPEG，勿使用含人脸的真实照片外传）
curl.exe -X POST http://YOUR_SERVER_IP:8000/detect `
  -H "X-Device-Key: CHANGE_ME_DEVICE_KEY" `
  -H "Content-Type: image/jpeg" `
  --data-binary "@path/to/test.jpg"
```

期望返回类似：

```json
{"action":"none","upright":true,"state":"upright","source":"fast","head_height":0.67,"shoulder_level":0.02,"reason":"fast_path_ok"}
```

### 3.2 登录服务器

```powershell
ssh <your-login-user>@YOUR_SERVER_IP
```

```bash
# 服务状态
systemctl status posture
# 实时日志（看每帧判定）
journalctl -u posture -f
# 只看判定行
journalctl -u posture -f | grep head_height
# 确认阈值已加载
journalctl -u posture | grep "startup, thresholds" | tail -1
```

### 3.3 从零部署（换服务器时）

```bash
# 1) 装系统依赖
sudo apt update
sudo apt install -y python3-venv python3-pip libgl1 libglib2.0-0

# 2) 放代码（本地执行，注意路径）
#    scp -r "学习状态监测系统\cloud\*" root@<新IP>:/opt/posture/

# 3) 建虚拟环境
cd /opt/posture
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt

# 4) 放模型（备份里已有，无需重新导出）
#    scp -r "服务器备份\model\yolov8n-pose_openvino_model" root@<新IP>:/opt/posture/

# 5) 配置
cp .env.example .env
nano .env        # 至少改 DEVICE_KEY；换 IP 不影响阈值

# 6) 装服务
cp posture.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now posture

# 7) 验证
curl http://127.0.0.1:8000/health
```

> ⚠️ `--workers` 必须为 **1**（单元文件已固定）。多进程会让"连续 2 帧"计数失效。
> ⚠️ 云控制台**安全组**要放行 8000，服务器本机 `ufw` 也要放行。
> ⚠️ 内存不要低于 4 GiB，模型编译会 OOM。

### 3.4 更快的方式：用重建脚本

```bash
# 上传 服务器备份/ 到新服务器
scp -r "服务器备份" root@<新IP>:/opt/posture_backup
ssh root@<新IP>
cd /opt/posture_backup
chmod +x rebuild.sh
./rebuild.sh
```

脚本会自动装依赖、建 venv、恢复模型与 `.env`、装 systemd、启动、自检（3~6 分钟）。
若提示应用代码缺失，把 `学习状态监测系统/cloud/*.py` 传上去再重跑。

## 4. 固件烧录

### 4.1 前提

| 项 | 要求 |
|---|---|
| ESP32 核心 | **3.x**（本机已装 3.3.12）；2.0.x **编不过** |
| 库 | `ArduinoJson` **7.x**（本机 7.4.3）；`esp32-camera` 随核心内置 |
| 开发板 | `AI Thinker ESP32-CAM` |
| 分区 | `Huge APP (3MB No OTA/1MB SPIFFS)`（**默认就是它**） |

### 4.2 改配置

编辑 `学习状态监测系统\firmware\config.h`：

```c
static const char* WIFI_SSIDS[WIFI_NET_COUNT] = {
  "你的WiFi名",     // 必须 2.4GHz
  "备用WiFi名",
  ""
};
static const char* WIFI_PASSWORDS[WIFI_NET_COUNT] = {
  "你的WiFi密码",
  "备用WiFi密码",
  ""
};
#define SERVER_URL  "http://YOUR_SERVER_IP:8000/detect"
#define DEVICE_KEY  "CHANGE_ME_DEVICE_KEY"
```

> 换服务器 → 改 `SERVER_URL`；换密钥 → 改 `DEVICE_KEY`，必须与云端 `.env` 一致，否则 401。

### 4.3 关键：Arduino 要求文件夹名与 .ino 同名

`firmware/main.ino` 所在目录叫 `firmware`，**不能直接编译**。
需要把它放进一个名为 `main` 的目录：

```powershell
# 建立编译暂存目录（已有 .build.archive\main 可参考）
New-Item -ItemType Directory -Force "项目\.build\main" | Out-Null
Copy-Item "学习状态监测系统\firmware\main.ino"   "项目\.build\main\" -Force
Copy-Item "学习状态监测系统\firmware\config.h"    "项目\.build\main\" -Force
```

### 4.4 用 arduino-cli 烧录（推荐，可脚本化）

```powershell
$cli = "__tools\arduino-cli\arduino-cli.exe"
$sketch = "项目\.build\main"

# 1) 查串口
& $cli board list

# 2) 编译（验证）
& $cli compile --fqbn esp32:esp32:esp32cam $sketch

# 3) 接线：GPIO0 接 GND，按一下 RST，然后上传
& $cli upload -p COM5 --fqbn esp32:esp32:esp32cam $sketch

# 4) 看日志（另开一个窗口）
& $cli monitor -p COM5 --config baudrate=115200
```

> `COM5` 换成实际串口。上传失败先检查 GPIO0 是否接地、是否按过 RST。

**本机实测（2026-10-18）**：esp32 核心 `3.3.12` + ArduinoJson `7.4.3`，
对 `项目\.build.archive\main` 执行上面的 compile 命令**通过**，
产物 `main.ino.bin = 1,191,504 字节`（1.14 MB），ELF 15.5 MB，
在 Huge APP（3 MB）分区内绰绰有余。

### 4.5 用 Arduino IDE 烧录

1. 打开 Arduino IDE → 把 `.build\main\main.ino` 拖进去（或先复制到 `main` 文件夹再打开）
2. 开发板选 `AI Thinker ESP32-CAM`
3. 分区选 `Huge APP (3MB No OTA/1MB SPIFFS)`
4. GPIO0 接 GND，按 RST
5. 点上传
6. 上传完成后断开 GPIO0，按 RST 重启
7. 串口监视器 115200 看日志

### 4.6 正常启动日志

```
[BOOT] posture monitor stage 1
[CAM] init ok
[WiFi] connected, IP: 192.168.1.100
[WEB] capture: http://192.168.1.100/capture
[BOOT] ready, state=NORMAL
[HTTP] resp: {"action":"none","upright":true,...}
```

## 5. 日常使用

### 5.1 怎么开始

1. 摄像头摆到**桌上正对面、平视、距头 0.5~0.6m**
2. 接通 5V 电源
3. 等串口打印 `ready`（或等 30 秒，它自己会上传第一帧）
4. 正常学习即可

### 5.2 它会怎么反应

| 你的状态 | 系统行为 |
|---|---|
| 坐直 | 每 10 秒静默上传，无任何提示 |
| 低头/驼背 **约 20 秒** | 风扇满速吹 **5 秒** + 红灯亮 |
| 持续不端正 | 每 **60 秒**再吹一次，不是连续吹 |
| 坐直了 | 立即停止提醒（红灯灭、风扇停） |
| 光线太暗 / 人不在 | 不上报判定，**不吹**（宁漏报不误报） |
| WiFi 断了 | 静默跳过本周期，下个周期自动重连 |

### 5.3 灯光与风扇的含义

| 现象 | 含义 |
|---|---|
| 红灯常亮 + 风扇转 | 正在提醒（5 秒） |
| 红灯灭、风扇停 | 正常监测中 |
| 红灯亮但风扇不转 | 旧设计里的免打扰态（**当前不会出现**，因按钮已禁用） |

### 5.4 怎么停

直接断电即可。系统无持久化状态，重新上电从 NORMAL 开始。

### 5.5 没有免打扰怎么办

当前版本**没有**手动静音（按钮因 GPIO0/XCLK 冲突被禁用）。
临时需要静音时：

- 把摄像头镜头盖住（暗光 → 无法判定 → 不吹），或
- 拔掉风扇电源（保留监测与红灯），或
- 改固件：把 `BUTTON_ENABLED` 改 1 并把 `PIN_BUTTON` 改到空闲脚（如 **15**），接一个按键到 GND。

## 6. 阈值标定

**什么时候需要标定**：换了摄像头位置、换了桌子/椅子、换人用，或发现误报/漏报。

### 6.1 方式一：手机快速标定（不用硬件）

```powershell
cd "学习状态监测系统\tools"
python capture_server.py
```

启动后终端会打印一个局域网地址（如 `http://192.168.1.100:8765`）。

1. 手机连**同一个 WiFi**，浏览器打开该地址
2. 把手机摆到真实使用位置
3. 自然坐直拍 3~5 张，记下 `head_height`（例如 0.67）
4. 刻意低头驼背拍 3~5 张，记下 `head_height`（例如 0.21）
5. 取中间值 `(0.67+0.21)/2 ≈ 0.44`，再**偏松一档**取 `0.37`
6. 侧歪：刻意歪肩拍几张，记下 `shoulder_level` 最大值，取其上方留余量作阈值

**写到服务器**：

```bash
ssh <your-login-user>@YOUR_SERVER_IP
nano /opt/posture/.env
#   HEAD_HEIGHT_MIN=0.37
#   SHOULDER_LEVEL_MAX=0.03
systemctl restart posture
journalctl -u posture | grep "startup, thresholds" | tail -1
# 期望：startup, thresholds: head_height_min=0.370 shoulder_level_max=0.030
```

### 6.2 方式二：离线批量标定（照片多时）

```bash
cd /opt/posture
source venv/bin/activate
python calibrate.py --upright ./samples/upright --slouch ./samples/slouch
```

输出两组样本的 `mean/P5/P50/P95/min/max` 与建议阈值。
目录结构：

```
samples/
├── upright/   端正样本 30 张
└── slouch/    不端正样本 30 张
```

> 参数是 `--upright` / `--slouch`（旧 README 写的 `--correct/--incorrect` 是错的）。

### 6.3 调参方向

| 问题 | 怎么调 |
|---|---|
| 坐直也被吹（误报） | **调低** `HEAD_HEIGHT_MIN`（更宽松） |
| 驼背不吹（漏报） | **调高** `HEAD_HEIGHT_MIN`（更严格） |
| 轻微歪肩就吹 | **调高** `SHOULDER_LEVEL_MAX` |
| 明显侧歪不吹 | **调低** `SHOULDER_LEVEL_MAX` |

原则：**先松后紧**、每次改 0.01~0.02、改完重启并观察一段。

## 9. 故障排查

### 9.1 按现象查

| 现象 | 最可能原因 | 处理 |
|---|---|---|
| 串口无输出 | 波特率不对 / TX-RX 未交叉 | 115200；交换 TX/RX |
| `[CAM] init failed` | 板子无 PSRAM / 供电不足 / 排线 | 换 5V/2A；检查排线金手指方向 |
| `[WiFi] first connect timeout` | SSID 错 / 5GHz / 信号弱 | 改用 2.4GHz；确认密码 |
| `[HTTP] failed, code=-1` | SERVER_URL 错 / 网络不通 | 先 `curl /health` |
| `code=401` | DEVICE_KEY 不一致 | 对齐固件与 `.env` |
| `code=500` | 服务器推理异常 | 看 `journalctl -u posture -f` |
| `[JSON] parse failed` | 响应不是 JSON（网关页/超时页） | 检查是否有反代/防火墙劫持 |
| 云端一直 `cannot_determine` | 太暗 / 人不在画面 / 距离远 | 补光；调整机位 |
| 一直 `upright:true` 但明明驼背 | 阈值太松 / 画面颠倒 | 调高 `HEAD_HEIGHT_MIN`；确认不是翻转问题 |
| 每 60 秒必吹（坐直也吹） | OV3660 未翻转 / 阈值错误 | 检查 `set_vflip`；确认阈值是 0.37/0.03 |
| 风扇不转 | GPIO13 接线 / S8050 方向 / 5V | 万用表量集电极；先直连 5V 试风扇 |
| 风扇一开就复位 | 无大电容 / 电源不够 | 并 1000µF；换 5V/2A |
| 设备每 5 分钟"离线" | 旧固件把 GPIO0 当按钮 | 确认 `BUTTON_ENABLED 0` 并重烧 |
| 服务起不来 | `.env` 格式 / 模型缺失 | `journalctl`；检查 `MODEL_DIR` |
| 改 `.env` 无效 | 没重启 / 无 `EnvironmentFile` | 重启；确认单元文件用的是修正版 |

### 9.2 快速定位"该吹不吹"

```bash
# 1) 云端收到帧了吗？判定是什么？
journalctl -u posture -f | grep head_height

# 2) 固件收到响应了吗？
#    串口：[HTTP] resp: {"action":"..."}

# 3) 云端说 blow 但风扇不转 → 硬件（GPIO13 / S8050 / 5V / 电机）

# 4) 云端一直 none 且 head_height 正常 → 规则计数（重启后需重新累计 2 帧）
```

### 9.3 已知非故障现象

| 现象 | 说明 |
|---|---|
| 偶发丢帧（约 2 帧/18s 而非 2 帧/20s 之外） | WiFi 波动，已接受 |
| 夜间不吹 | 暗光无法判定，设计如此 |

## 11. 注意事项

### 11.1 安全

| 项 | 现状 | 建议 |
|---|---|---|
| 服务器登录 | root + 密码登录开启 | 改 `PermitRootLogin prohibit-password` |
| `DEVICE_KEY` | 明文写在固件与 `.env` | 曾泄露，介意可轮换（`openssl rand -hex 16`） |
| WiFi 密码 | 明文在 `config.h` | 分享工作区前脱敏 |
| 传输 | HTTP 明文 | 敏感环境建议上 HTTPS |

### 11.2 不要做的事

- ❌ 不要用 ESP32 core 2.x 编译本固件（会报 `ledcAttachChannel` 不存在）
- ❌ 不要把风扇直接接 GPIO（会烧芯片）
- ❌ 不要在没有 1N5819 的情况下用三极管驱动电机
- ❌ 不要用 `--workers 2` 以上（连续 2 帧逻辑失效）
- ❌ 不要直接改 `历史/旧版副本-.../` 里的代码（那是归档，不是权威）
- ❌ 不要上电瞬间按住 GPIO0（会进下载模式）

### 11.3 改代码后必做

1. 改 `学习状态监测系统/cloud/` → 重新部署到 `/opt/posture/` → `systemctl restart posture`
2. 改 `firmware/` → 重新复制到 `main` 目录 → 重新编译烧录
3. 改完在 `docs/项目文档.md` 的配置矩阵同步更新

### 11.4 文件在哪

| 要找什么 | 位置 |
|---|---|
| 权威代码 | `学习状态监测系统/` |
| 固件配置 | `学习状态监测系统/firmware/config.h` |
| 云端配置模板 | `学习状态监测系统/cloud/.env.example` |
| 灾备（模型/密钥/重建） | `服务器备份/` |
| 服务器信息与运维 | `服务器/` |
| 硬件原始项目与测试记录 | `项目/` |
| 工具链 | `__tools/` |
| 旧版本/旧文档 | `历史/` |
