# 模型 A/B 报告 · yolov8n-pose vs yolov8s-pose

> 日期:2026-11-09
> 服务器:`YOUR_SERVER_IP`(2 vCPU / 1.6 GiB),OpenVINO 2026.4.1
> 数据集:
> - **真机集**:`20261109-215838` ~ `20261109-220022` 四个会话共 **152 帧**(设备实拍,含 180° 倒装,已复现线上 auto-rotate)
> - **标注集 A**(项目金标准):`images/test` 24 张,其中 19 张有 `upright` 布尔标签

## 一、结论先行

| 维度 | yolov8n | yolov8s | 谁赢 |
|---|---|---|---|
| OpenVINO 推理延迟(生产同管线) | **86.6 ms** | 240.3 ms | n(但两者都远低于预算) |
| 上传预算占用(10 s/帧) | 0.87% | 2.40% | 都无压力 |
| 模型体积 | 13.4 MB | 46.7 MB | n |
| 真机 152 帧可用率 | **100%**(152/152) | 98.7%(150/152) | n |
| 真机 `head_height` 负值率 | **2.0%** | 9.3% | **n** |
| 真机 `shoulder_level` 均值 | 0.0088 | 0.0188 | n(更稳) |
| 真机 判端正比例(0.28/0.10) | 53.3% | 54.0% | 平 |
| 标注集 A 可用帧准确率 | 66.7% | **71.4%** | s |
| 标注集 B 可用帧准确率 | 68.5% | **74.5%** | s |
| 标注集 B `upright` 类判对率 | 50.0% | **66.7%** | s |
| 标注集 B `slouch` 类误判端正 | 22.2% | **10.0%** | s |

**判定:不建议现在换 s。**

理由见第四节 —— 关键指标在**真机域上没有改善,反而在负值率上变差**;s 的优势全部来自 web 素材域。

## 二、延迟

同一份 `app.preprocess` + `app.infer` 管线,单张 640×640,30 次取统计:

```
yolov8n  mean=86.6ms  P50=86.5ms  P95=88.5ms  max=88.5ms  size=13.4MB
yolov8s  mean=240.3ms P50=239.8ms P95=244.1ms max=254.7ms size=46.7MB
```

- 上传间隔 10 000 ms,当前占用 **0.87%**;
- 换 s 后占用 **2.40%**,依然完全不是瓶颈;
- 注意:这条链路上真正慢的是**慢通道**(平均 9.5 s),不是 pose 模型。

**所以"换大模型会不会太慢"这个顾虑不成立。**

## 三、质量:两个域的表现差异

### 3.1 真机域(152 帧,无标签,只看几何稳定性)

| 指标 | n | s |
|---|---|---|
| 可用帧 | 152/152 | 150/152 |
| hh 均值 | 0.334 | 0.341 |
| hh P5 | 0.009 | **-0.010** |
| **hh 负值率** | **2.0%** | **9.3%** |
| sl 均值 | 0.0088 | 0.0188 |
| sl P95 | 0.0161 | 0.0348 |
| sl 最大值 | 0.0247 | 0.0682 |
| 判端正比例 | 53.3% | 54.0% |

**两条关键观察**

1. **s 的 `shoulder_level` 系统性翻倍**(0.0088 → 0.0188),但最大值 0.068 仍远低于当前阈值 0.10 —— 所以今晚刚调的肩线阈值**不会被击穿**。
2. **s 的 `head_height` 负值率是 n 的 4.6 倍**(2.0% → 9.3%)。
   负值意味着鼻子被回归到肩线下方,几何已失真。这恰恰是优化建议 §4.1 想用大模型解决的问题,实测**反向**了。

不过:判端正比例几乎相同(53.3% vs 54.0%),说明这些差异在最终决策上互相抵消了。

### 3.2 标注域(web 素材,有 ground truth)

| 指标 | n | s |
|---|---|---|
| A 集(19 张)可用帧准确率 | 66.7% | **71.4%** |
| A 集整体准确率(含不可用) | 52.6% | 52.6% |
| B 集(80 张)可用帧准确率 | 68.5% | **74.5%** |
| B 集覆盖率 | 67.5% | 63.7% |
| B 集整体准确率 | 46.3% | 47.5% |
| `upright` 类覆盖率 / 判对率 | 100% / 50% | 90% / **67%** |
| `slouch` 类覆盖率 / 误判端正 | 90% / 22.2% | 100% / **10.0%** |

s 在 web 域上确实更好:**可用帧准确率 +6pp**,`upright` 类判对率 **+16.7pp**,`slouch` 误判端正率**砍半**。

> ⚠️ 但 web 素材与部署域差距很大:分辨率、构图、光照、机位距离都不同。
> 而且这些图用的是**项目相机标定出来的阈值**(0.28/0.10),拿来评 web 图本身就不公平 ——
> 绝对数字只可同向比较,不可当验收指标。

## 四、为什么不建议现在换

1. **真机域没有可测量的收益**:判端正比例 53.3% vs 54.0%,差异在噪声范围内。
2. **在唯一有 ground truth 的真机指标上更差**:hh 负值率 2.0% → 9.3%。
   `head_height` 是快通道的核心判据,负值意味着几何不可信;虽然最终判定被抵消,但这是把"看得准"换成了"碰巧抵消"。
3. **成本不是 0**:模型从 13 MB 涨到 47 MB,换模型后**所有阈值必须重新标定**(hh/sl 数值全部平移),而标定要靠现场采集,不是改个配置。
4. **真正的瓶颈不在这里**。今晚的实测反复指向同一件事:
   - 快通道失效原因里 `low_kp_conf` 占绝对多数;
   - 而 `low_kp_conf` 的根因是**取景**(头肩不在画面内)和**3 关键点严格判定**(缺一个就整帧作废);
   - 前者靠摆位/标定解决,后者靠优化建议 §1.2(9 关键点 + presence)解决。
   换更大模型对这两条都不对症。

---

## 五、如果之后仍想换,正确的做法

1. **先补真机标注集**:同一机位、同一人,正坐 / 驼背 / 侧身 / 撑头各 ≥30 帧,存成带标签的目录;
2. **用该集跑 A/B**,而不是用 web 图;
3. 若 s 在真机集上 `low_kp_conf` 率显著下降,再换;
4. 换完**必须重标定** `HEAD_HEIGHT_MIN` / `SHOULDER_LEVEL_MAX`,因为两者数值随模型漂移(本次实测 sl 均值翻倍);
5. 同期把 §1.2(9 点 + presence)一起做,否则单靠换模型提升有限。
