## 二、三道闸门：先剔除，再排序

每个后端在参与选路前要过三关：

```
① 能力探测   启动时各发一张 1x1 图；连图都不收的标记 supports_vision=False → 永不选
② 熔断器     circuit breaker：连续 3 次失败 → 停用 120 秒
③ 已试过     本轮已经被调用过的不再重复选
```

### 熔断的两个触发方式

| 情况 | 处理 |
|---|---|
| 网络错误 / 5xx / **200 但 content 为空** | `fail()` 计数 +1，满 3 次跳闸 |
| `401 / 403 / 404`（`PERMANENT_CODES`） | **立即**跳闸，不再浪费重试 |

> "200 但 content 为空"也算失败——这是 OpenRouter 推理模型截断、以及
> ModelScope 空返回的实际教训（见 §七）。

## 三、串行模式（`_pick`）

```
主用可用 → 永远只用主用（主备语义，不轮转）
主用不可用/已试过 → 备用里挑 EWMA 最小的
从未测过速 → 排在最后，但仍可用（防止冷启动全挂）
```

每次失败后按 `0.8 × 2^n + 抖动` 退避，最多重试 `AI_MAX_TRIES=2` 次。

## 四、并行模式（默认，`AI_PARALLEL=true`）

### 4.1 选目标（最多 3 个）

```
① primary 必选（质量基线，不参与速度竞争）
② 剩余名额：先挑"不同账号"里最快的各一台 —— 多账号配额独立，落在同一账号会互相抢限流
③ 名额还有剩，再按 EWMA 补同一账号的
```

**线上实例**（`GET /pool` 实测 EWMA）：

```
primary      sensenova             0.00（未参与测速，必选）
fallback8    Sage-A1.5    discovery    0.63  ← 第 2 个（discovery 最快）
fallback9    Sage-A1.5    discovery    0.67  （同域名，跳过）
fallback2    Sage-A1.5    discovery    0.69  （同域名，跳过）
fallback13   gpt-4.1-mini chatanywhere 1.13  ← 第 3 个（新账号）
```

→ 本轮目标 = **sensenova + Sage-A1.5 + gpt-4.1-mini**（三个不同账号）

日志印证：`vote2/2 model=sensenova-6.8-flash-lite,gpt-4.1-mini`

### 4.2 发送

- 3 路并发，**每路间隔 150ms**（`parallel_stagger`），避免同一网关瞬时 429
- 最多等 `AI_PARALLEL_DEADLINE=15s`；超时未回的线程直接放弃
  （用 `shutdown(wait=False)`，否则退出时会 join 慢线程，实测把 12s 拖成 16.2s）

### 4.3 投票

```
按 upright 分组 → 取票数最多的阵营
  票数 ≥ quorum(2) → 采用该阵营
  票数 < quorum    → 退化为"置信度最高的单条"
获胜阵营内取 confidence 最高者作为最终 JSON
```

结果标记为 `vote{阵营票数}/{有效返回数}`，例如 `vote2/2`、`vote3/3`。

## 五、速度学习（EWMA）

```
alpha = 0.3
latency_ewma ← 0.3 × 本次耗时 + 0.7 × 旧值
失败也计入（按超时值惩罚，等于自动降权）
```

启动时并发给所有**备用**后端各发一张 1x1 图做种子测速
（主用不测，靠真实调用刷新）。

## 七、几个刻意的设计取舍

### 7.1 primary 不参与速度竞争

它要当"质量基线"，所以永远占一个名额，即使比备用慢。
代价：若 primary 变慢，每轮都白白等它到 deadline。

### 7.2 优先不同账号而非绝对最快

同样的速度下，跨账号能避免限流互抢。实测 discovery 一组 6 个 key 都在
`api-forecast` 同一域名，同时打三个必然 429。

### 7.3 推理型后端单独放大 max_tokens

`nemotron-3.5-super-vl:free` 的 reasoning 会吃掉 877 token，
`max_tokens=800` 时 content 直接为空。所以有 `AI_FALLBACK{n}_MAXTOKENS` 覆盖。

### 7.4 免费档只当兜底

OpenRouter 免费档 **50 次/天**，我们每小时约 120 次抽查，
所以它排在 `fallback14`，靠 EWMA（4.17s）自然被排到最后。

## 八、当前策略的弱点

| 弱点 | 影响 | 可能改法 |
|---|---|---|
| primary 不测速 | 主用慢了会拖满 deadline | 让 primary 也参与 EWMA 竞争 |
| 没有"每日配额"概念 | 免费档后端可能被选中后快速耗尽 | 加 `AI_FALLBACK{n}_DAILY_LIMIT` 计数 |
| 只按域名分账号 | 同域名的不同 key 其实配额独立 | 支持显式 `AI_FALLBACK{n}_ACCOUNT` 分组 |
| 投票只看 upright | state 可能来自获胜阵营里另一个模型 | 按 state 一致性做二次裁决 |
| 无跨轮记忆 | 每轮独立选，不看上一轮谁失败 | 加短期失败记忆（已有熔断，粒度较粗） |
