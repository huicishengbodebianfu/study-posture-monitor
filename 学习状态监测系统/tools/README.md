# 手机拍照测试工具

> `capture_server.py` — 用手机当临时摄像头，拍照直接送云端 `/detect`，当场看到判定结果

## 一、这个工具解决什么问题

**原本的标定流程很麻烦**：烧录 Arduino 示例 `CameraWebServer` → 串口里找局域网 IP
→ 浏览器打开 → 点 Start Stream → 对着摄像头摆姿势 → 右键保存图片 → 重复 60 次
（端正 30 张 + 不端正 30 张）→ 跑 `calibrate.py` 算阈值。

中间任何一步出错（摄像头没插好、WiFi 不通、PSRAM 不认）都会卡住，
**而这些硬件问题本来和"标定阈值"这件事无关**。

**这个工具把标定从硬件里解耦出来**：

- 用手机当摄像头，画质比 ESP32-CAM 好得多，也不用等硬件到位
- 拍完立刻上传、立刻看到 `head_height` 数值，**不用保存文件、不用跑脚本**
- 屏幕上有大字结论（端正 / 不端正 / 无法判定），手机举着就能看
- **只用 Python 标准库**，不需要装任何第三方包

**适用场景**：ESP32-CAM 还没买、没烧录，或者烧录出问题时，先把阈值标出来。

## 二、怎么用

### 前置条件

- 一台笔记本（Windows / macOS / Linux 都行），装了 Python 3
- 一部手机
- **手机和笔记本连同一个 WiFi**

### 启动

```bash
cd tools
python capture_server.py
```

启动后会打印：

```
==============================================================
  坐姿检测 · 手机拍照测试
==============================================================
  手机浏览器打开：  http://192.168.1.100:8765

  转发目标：        http://YOUR_SERVER_IP:8000/detect
  设备密钥：        239f9e11…（已隐藏后段）

  手机需与本机连同一个 WiFi。按 Ctrl+C 停止。
==============================================================
```

### 手机上操作

1. 浏览器打开上面那个网址（`http://192.168.x.x:8765`）
2. 把手机摆到**真实使用位置**——桌上正对面、平视、离头 0.5~0.6m
3. 点「拍照」（或「从相册选」）
4. 等 1~2 秒，屏幕上出现结果

### 看结果

页面会显示：

| 显示项 | 含义 |
|---|---|
| **大字结论** | 端正（绿）/ 不端正（红）/ 无法判定（灰） |
| **头高 head_height** | **标定就靠这个数**。坐直时大，低头驼背时小 |
| **肩平差 shoulder_level** | 侧歪时变大 |
| **动作 action** | `blow` 表示会触发吹风 |
| 判定来源 / 状态 / 原因 | 调试用 |
| 最下方 JSON | 原始返回，完整字段 |

## 三、标定怎么算阈值

**核心就一句话**：取"坐直时的数值"和"驼背时的数值"的中间值。

### 操作步骤

1. 自然坐直（别刻意挺直），拍 3~5 张，记下 `head_height`，比如都是 **0.68** 左右
2. 刻意低头驼背，拍 3~5 张，记下 `head_height`，比如都是 **0.21** 左右
3. 算中间值：`(0.68 + 0.21) / 2 ≈ 0.44`
4. **实际取偏松一档**，比如 **0.37**（原则：先松后紧，初期宁可漏报也别频繁误报）

### 写到服务器上

```bash
ssh admin@YOUR_SERVER_IP
sudo nano /opt/posture/.env
# 改这两行：
#   HEAD_HEIGHT_MIN=0.37
#   SHOULDER_LEVEL_MAX=0.03
sudo systemctl restart posture

# 确认新阈值已加载
sudo journalctl -u posture -o cat | grep "startup, thresholds" | tail -1
# 应输出：startup, thresholds: head_height_min=0.370 shoulder_level_max=0.030
```

> 页面底部显示的"服务器当前阈值：头高 < 0.15 判低头"是**硬编码的提示文字**，
> 不会随服务器配置更新。改完阈值后以 `journalctl` 的输出为准。

### 实测值参考（2026-09 标定记录）

| 姿势 | head_height | shoulder_level |
|---|---|---|
| 自然坐直 | **0.6798** | 0.0050 |
| 刻意驼背 | **0.2067** | 0.0065 |

最终采用：`HEAD_HEIGHT_MIN=0.37`、`SHOULDER_LEVEL_MAX=0.03`

> ⚠️ 注意肩平差两组的差距很小（0.0050 vs 0.0065），说明当时**侧歪动作做得不明显**，
> 导致侧歪检测不太可靠。重新标定时请刻意把肩膀歪得明显一些。

## 四、配置

脚本开头有三个常量：

```python
SERVER_DETECT = "http://YOUR_SERVER_IP:8000/detect"   # 云端接口地址
DEVICE_KEY    = "CHANGE_ME_DEVICE_KEY"    # 设备密钥，必须与云端一致
LISTEN_PORT   = 8765                                   # 本地监听端口
```

**服务器 IP 或密钥变了，必须改这里**，否则上传会返回 401 或连不上。

如果 8765 端口被占用，可以启动时临时指定：

```bash
python capture_server.py 8766
```

## 五、常见问题

| 现象 | 原因与解决 |
|---|---|
| 手机打不开网址 | 手机和电脑不在同一个 WiFi；或电脑防火墙拦了 8765 端口 |
| 页面打开但上传失败，HTTP 401 | `DEVICE_KEY` 与服务器 `/opt/posture/.env` 里的不一致 |
| 上传失败，HTTP 000 / 超时 | 服务器 IP 填错，或服务器安全组没放行 8000 |
| 一直显示「无法判定」 | 光照太暗、人不在画面里、或人离得太远（关键点置信度 < 0.5） |
| 「双肩重合，无法计算肩宽」 | 拍摄角度太偏，肩膀在画面里几乎重合成一点，调整手机角度 |
| 启动报端口占用 | 换端口：`python capture_server.py 8766` |

## 六、它和正式系统的区别

| | 这个工具 | 正式系统（ESP32-CAM） |
|---|---|---|
| 摄像头 | 手机 | ESP32-CAM |
| 触发上传 | 手动点按钮 | 每 10 秒自动 |
| 结果呈现 | 手机网页 | 无（直接控制风扇/LED） |
| 用途 | **标定阈值、验证算法** | 实际监测 |
| 是否经过"连续2帧"逻辑 | **否**（单张直接判定） | 是 |

> ⚠️ 这个工具走的也是 `/detect` 接口，**所以它会计入服务器的"连续 2 帧"计数**。
> 用它连拍多张不端正照片时，服务器可能真的返回 `action: "blow"`——
> 这是正常的，但如果同时有 ESP32 在跑，风扇可能真的会转。
