# 安卓端(APK)· 拍照上传实施方案

> **状态**:草案 v0.1 · 2026-10-08
> **位置**:`学习状态监测系统/android/`(与 `cloud/`、`firmware/`、`tools/` 并列,权威版一处分口)
> **一句话**:把"ESP32-CAM 拍照上传"这一段用手机 APK 复现——手动点拍、或每 10 秒自动拍一张,
> POST 到云端 `/detect`,结果页用大字给出「端正 / 不端正 / 无法判定」,并支持标定样本的采集与导出。
> **§9 有 7 条待确认**(均已给建议默认值,本文正文按默认值拟写)。

---

## 1. 为什么要做安卓端

| 现状痛点 | APK 如何解决 |
|---|---|
| ESP32-CAM 硬件侧未完成(烧录 / 风扇接线 / 全链路联调均待做) | 手机就是现成的摄像头与算力载体,先行跑通"采集 → 判定"闭环 |
| 现有 `tools/capture_server.py` 要求「电脑常开 + 手机连同一 WiFi + 开浏览器」 | 装一个 APK 即可,手机直连公网服务器,不依赖电脑 |
| 标定样本靠肉眼读数、手抄,无法留档 | 自动记录每一帧的数值,一键导出 CSV |
| 相机画质:ESP32-CAM 为 VGA(640×480) | 手机可拍更高分辨率,关键点更稳(型号仍以标定为准) |

**定位**:安卓端是**采集与观测端**,不是替代品。阶段一"风扇吹风"的最终提醒仍由 ESP32 承担;
手机端在硬件到位前充当标定与验证工具,到位后可继续作为便携监测与数据采集入口。

## 2. 决策记录(承接既有 D1~D13,新增 D14~D24)

| 编号 | 决策项 | 结论 | 为什么 |
|------|--------|------|--------|
| D14 | 形态 | **原生 Android APK**(Kotlin),不做网页 / PWA | 要调相机、要后台定时、要能离线留档 |
| D15 | 用途 | **日常监测 + 标定采集**(两者都要) | 硬件未完工期间一物两用 |
| D16 | 手动模式拍照 | **调用系统相机**(`ACTION_IMAGE_CAPTURE`) | 代码最少、兼容性最好、无需申请相机权限 |

| D18 | 上传节奏 | 自动模式 **10 秒/帧**(与固件 `UPLOAD_INTERVAL_MS` 一致) | 与 ESP32 行为对齐,便于对照与标定 |
| D19 | 云端 | 阿里云 `http://YOUR_SERVER_IP:8000/detect` | 实测在线;AWS 那台**未部署服务**(实测无响应) |
| D20 | 服务器可配置 | 设置页可改 **URL / DEVICE_KEY / 间隔** | 服务器 10-25 到期,IP 必变,避免重新出包 |
| D21 | 结果呈现 | 大字结论 + `head_height` + `shoulder_level` + `action` + 原始 JSON 折叠 | 沿用 `tools/capture_server.py` 的版式 |
| D22 | 连续 2 帧 | App 显示「第 N/2 帧」,与服务器计数对齐展示 | 手机单张拍照时行为可预期 |
| D23 | 兼容性 | `minSdk 24`(Android 7.0)/ `targetSdk 35` / `compileSdk 35` | 覆盖面最大化;35 为本机已装平台 |
| D24 | 工程位置 | `学习状态监测系统/android/` | 与 cloud / firmware 并列,权威版收口 |

**沿用既有决策**:D2(桌上正对面平视,距头 0.5~0.6m,手机需支架)、D5(连续 2 帧 / 60s 重提醒)、
D6(先松后紧)、D9(暗光宁漏报不误报)、D11(不动模型)。

## 3. 接口契约(以线上实测为准)

### 3.1 请求

| 项 | 值 |
|---|---|
| 方法 / 地址 | `POST http://YOUR_SERVER_IP:8000/detect` |
| 请求头 | `X-Device-Key: <密钥>`;`Content-Type: image/jpeg` |
| 请求体 | **JPEG 原始二进制**(不是 multipart) |
| 健康检查 | `GET /health` → `{"status":"ok"}`(实测 HTTP 200) |

### 3.2 响应(实测样本,2026-10-08)

```json
{"action":"none","upright":null,"state":"unknown","source":"fused","reason":"cannot_determine"}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `action` | string | `blow` 触发提醒 / `none` 不触发 |
| `upright` | bool/null | `true` 端正 / `false` 不端正 / `null` 无法判定 |
| `state` | string | 状态标记(与 `source` 一同由融合层产生) |
| `source` | string | 判定来源(`fast` 快速通道 / `fused` 融合兜底) |
| `head_height` | float | 头高比,**标定核心数值**(仅快速通道命中时返回) |
| `shoulder_level` | float | 肩平差,侧歪时变大(同上) |
| `reason` | string | 无法判定或异常的原因 |

### 3.3 服务端行为(必须记住的三条)

1. **`--workers 1`**:单进程内存态计数器,「连续 2 帧」与「60 秒去重」都靠它。
2. **计数是全局共享的**:手机与 ESP32 同时上传会**互相干扰**(见 §9-C)。
3. **错误码**:`401` 密钥错 / `400` 空请求体 / `500` 推理失败 / `-1` 连不上(固件侧同义)。

### 3.4 当前生效配置

- 阈值:`HEAD_HEIGHT_MIN=0.37`、`SHOULDER_LEVEL_MAX=0.03`
- 多态检测(慢速通道):**关闭** → `source:"fused"` 多为"两通道都判不出"的兜底标记

## 6. 技术方案

| 项 | 选型 | 依据 |
|---|---|---|
| 语言 | Kotlin | 与 `C:\vf\sample\Android` 参考工程一致,语法简洁 |
| 构建 | AGP **8.7.3** + Gradle **8.11.1** | 8.11.1 发行版**本机已缓存**(`~/.gradle/wrapper/dists`),免下载 |
| JDK | **17**(本机 17.0.12) | AGP 8.7 要求 JDK 17 |
| SDK 路径 | `C:\Program Files (x86)\Android\android-sdk` | 本机实测已装 platforms 35/36、build-tools 36.0.0 |
| UI | XML 布局 + ViewBinding + Material Components | 不用 Compose,降低构建重量与出错面 |
| 网络 | OkHttp(同步调用置于后台线程) | 二进制 body 直发,超时可控 |
| JSON | `org.json`(系统自带) | 零额外依赖,字段少 |
| 相机 | 手动:`ACTION_IMAGE_CAPTURE`;自动:CameraX | 见 §9-A |
| 存储 | SharedPreferences(设置)+ 应用私有目录(CSV) | 免申请存储权限 |
| 图片 | 长边缩至 **1280**、JPEG 质量 **80** | 模型入参固定 640×640,过高无益;见 §9-F |
| 并发 | 单线程串行上传(避免自撞"连续 2 帧") | 与固件一问一答模型一致 |

**权限清单**:`INTERNET`(必须)、`CAMERA`(自动模式)、`POST_NOTIFICATIONS`(若选前台服务)。

## 10. 风险与已知限制

| 风险 | 影响 | 应对 |
|---|---|---|
| 服务器 **2026-10-25 到期** | IP 变更 → 旧 APK 失效 | 服务器地址可设置;到期前迁移或续费 |
| 与 ESP32 共享"连续 2 帧"计数 | 两者同时跑会互相干扰 | 第一版不同时开;§9-C |
| 后台相机限制(Android 9+、14 更严) | 息屏后自动模式停摆 | 前台 + 屏幕常亮;或前台服务(`camera` 类型) |
| 首次构建需联网下载依赖 | 无网环境构建失败 | 已验证仓库可达;可先 `assembleDebug` 预热缓存 |
| APK 反编译可读 `DEVICE_KEY` | 密钥泄露(该密钥历史上已泄露过) | 密钥可运行时可填;建议轮换(需同步云端与固件) |
| 手机画质 / 角度 ≠ 标定样本 | 判定偏差、误报 | 用 APK 自己的样本重新标定,再回填云端阈值 |
| 隐私:照片上云 | 已接受(云端不落盘) | 默认不在手机留图 |
| 手机需固定机位(D2) | 手持会破坏判定一致性 | 需手机支架,距头 0.5~0.6m、平视 |

## 11. 验收标准

1. 真机安装成功,`minSdk 24` 及以上可运行。
2. 手动拍一张 → **1~2 秒**内显示结论与 `head_height`。
3. 自动模式按设定间隔连续上传,界面显示「已上传 N 张」与「第 N/2 帧」。
4. 连续两帧不端正时,界面明确提示"已触发提醒"。
5. 设置页修改服务器地址 / 密钥后**立即生效,无需重装**。
6. 导出 CSV 可在电脑上正常打开,列完整、数值与界面一致。
7. 断网、密钥错误(401)、服务器超时均给出**明确提示且不崩溃**。
8. 与 ESP32 或 `curl` 上传同一张照片,判定结果一致(排除随机性)。

## 13. 与其他模块的衔接

| 模块 | 关系 |
|---|---|
| `cloud/` | 本端只调用 `/detect`、`/health`,**不改云端代码**(除非采纳 §9-C 的隔离方案) |
