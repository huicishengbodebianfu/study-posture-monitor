# OLED 显示改版方案：`BAT --` → 有人 / 无人 / 看不清

> **目标**：USB 直供、不装电池；OLED 第 4 行不再显示 `BAT --`，改为显示快通道“是否有人”。
> **依据**：`服务器-OLED接口说明.md`（`/detect` v2）
> **边界**：只给方案，不改代码；接线、风扇、上传逻辑都不动。

---

## 0. 结论（推荐方案）

| 项 | 方案 |
|---|---|
| 数据源 | `/detect` v2 的 **`scene`** 字段（`person` / `empty` / `occluded`） |
| 显示 | **有人 / 无人 / 看不清** |
| OLED 位置 | 替换第 4 行 `BAT xxV xx%`；前 3 行不变 |
| 去抖 | `person` 立即显示；`empty` / `occluded` **连续 2 帧**才切换（约 20 秒） |
| 超时 | 30 秒没有成功响应 → **离线**；刚上电 → **检测中…** |
| 电池 | 不再显示；电池检测可关闭（GPIO1 10k 下拉或保留分压但忽略） |
| 服务端 | **不需要改**，v2 已上线 |

> **不要只用 `person` 布尔值**：`person=false` 同时包含“空座位”和“镜头被挡/太暗”，
> 只看 `person` 会把“看不清”误显示成“无人”。必须用 `scene`。

---

## 1. 数据源与语义

`/detect` v2 新增字段：

| 字段 | 用途 |
|---|---|
| `v` | 协议版本，当前 2 |
| `person` | 快通道是否检出人体（**不等同于“有人在”**） |
| `scene` | `person` / `empty` / `occluded`，快通道场景三分类 |
| `display` | 短码，服务器建议给 OLED 用（含姿态） |
| `display_cn` | 中文文案，调试用 |

### 为什么用 `scene`，不用 `person` / `state`

- `person=true` → 画面里有人（YOLO 人体得分 ≥0.5）。
- `person=false` → 没人 **或** 看不清；必须看 `scene` 区分。
- `state` 可能来自慢通道缓存（TTL 45 秒），会滞后；
  `scene` 是即时算的，适合做“有人/无人”实时显示。
- `display` 更适合“完整姿态显示”（端正/低头/侧歪/手机/走神/趴桌），
  但其中 `LEAN/PHONE/DAZE/SLEEP` 可能来自慢通道；本需求只做“是否有人”，用 `scene` 最直接。

## 2. 显示映射

| `scene` | OLED 第 4 行 | 含义 | 去抖 |
|---|---|---|---|
| `person` | **有人** | 画面里有人 | 立即 |
| `empty` | **无人** | 空座位，真没人 | 连续 2 帧 |
| `occluded` | **看不清** | 手挡镜头/关灯/朝墙/朝天花板 | 连续 2 帧 |
| 字段缺失 | **未知** | 老服务器/解析失败 | — |
| 30 秒无响应 | **离线** | 没 WiFi / 上传失败 / 服务异常 | — |
| 刚上电无结果 | **检测中…** | 还没收到第一帧结果 | — |
| 摄像头故障 | **—** | `cam_ok=false`，状态行已显示“摄像头故障” | — |

> 如果产品坚持“只显示有人/无人”两态：`person=true`→有人，`person=false`→无人。
> 但 `occluded` 会被误显示成“无人”，**不推荐**；至少保留“看不清”三态。

## 3. OLED 布局

### 现在（USB 直供、无电池）

```
学习坐姿监测          ← 12px 中文
正常监测              ← 16px 中文
WiFi 192.168.x.x      ← 6x10
BAT --                ← 6x10（要删掉）
```

### 改后

```
学习坐姿监测          ← 12px 中文
正常监测              ← 16px 中文
WiFi 192.168.x.x      ← 6x10
有人                  ← 12px 中文（替换 BAT 行）
```

- 第 4 行用 **12px 中文字体**（和标题同款即可），`有人`/`无人`/`看不清` 都放得下。
- 不建议加“快:”前缀：128×64 空间有限，状态行已经够满。
- 若以后想同时显示姿态，可改成 `有人 · 低头`（12px 下约 60px，也能放下），
  但本方案先只做“是否有人”。

## 4. 更新、去抖与超时

### 4.1 更新节奏

- 固件每 **10 秒**上传一帧，`/detect` 返回后解析 `scene`。
- OLED 本身 1 秒刷一次，但“有没有人”只在收到新结果时更新，不需要更快。
- 保留“最后一次成功响应时间”，用于超时判断。

### 4.2 两帧去抖（重点）

服务器文档明确建议：`AWAY`/`DIM` 做 2 帧确认，避免 YOLO 单帧漏检导致屏幕闪烁。

| 新结果 | 处理 |
|---|---|
| `person` | **立即**显示“有人” |
| `empty` | 连续 2 帧都是 `empty` 才显示“无人”；第 1 帧先保持原显示 |
| `occluded` | 连续 2 帧都是 `occluded` 才显示“看不清” |
| `person` ↔ `empty/occluded` | 以“有人”优先：看到人立即显示；人要连续 2 帧没人才算离开 |

> 2 帧 × 10 秒 = 约 20 秒确认；如果觉得“人走了还显示有人”太久，
> 可改成 1 帧 + 保持 15 秒，但闪烁风险会变大。

### 4.3 超时

| 条件 | 第 4 行 |
|---|---|
| 上电后还没收到第一帧 | `检测中…` |
| 最近 30 秒没有成功响应（约 3 个上传周期） | `离线` |
| 摄像头 `cam_ok=false` | `—`（状态行显示“摄像头故障”） |
| HTTP 401/500 / JSON 解析失败 | 计入失败；30 秒后 `离线` |

> 不要长时间保留旧的“有人”：人可能已经走了，显示“离线”比显示过期结果诚实。

## 5. 异常与降级

| 情况 | 第 4 行 | 状态行 | 备注 |
|---|---|---|---|
| 正常有人 | 有人 | 正常监测 | 绿灯 |
| 空座位 | 无人 | 正常监测 | 绿灯，不吹风 |
| 手挡/关灯 | 看不清 | 正常监测 | 绿灯；不要显示“无人” |
| 摄像头坏 | — | 摄像头故障 | 黄灯 |
| 没 WiFi / 上传失败 | 离线 | 网络异常（原“低电量/异常”改名） | 连续失败 3 次转黄 |
| 老服务器无 `scene` | 未知 | 正常监测 | 不猜“无人” |
| 吹风提醒 | 有人 | 吹风提醒 | 红灯闪、风扇 5 秒；第 4 行不受影响 |

## 6. 与电池、状态灯的关系

### 6.1 电池检测

USB 直供、不装电池后：

- OLED 不再显示 `BAT --`；
- 分压的 2 只 10k + 100nF **可以不装**；
- 如果已经焊了分压，保留也不影响；不装电池时下臂 10k 会把 GPIO1 拉到 0V；
- **纯 USB、GPIO1 悬空**时，ADC 可能偶发落入 2.5~5.2V，被当成“低电”，所以要么保留分压，要么 **GPIO1 用 10k 下拉到 GND**。

> 建议在固件配置里加一个“电池检测关闭”开关，或直接把 `battery_valid` 固定为 false；
> 这样状态行不会再出现“低电量”。

### 6.2 状态行

现在 `stateLabel()` 的低电量/上传失败共用“低电量/异常”文案。USB 直供后建议：

- 去掉 `batteryLow` 判断；
- 上传连续失败 3 次时显示 **“网络异常”**（不要叫“低电量”）；
- 吹风/免打扰/摄像头故障逻辑不变。

### 6.3 状态灯

- 去掉“低电量”黄灯来源；
- 黄灯只保留：摄像头故障、上传连续失败 ≥3 次；
- 吹风红灯闪、免打扰红灯常亮、正常绿灯都不变。

## 7. 需要改的位置（只列位置，不写代码）

| 位置 | 改动 |
|---|---|
| `main.ino` 的 `uploadAndHandle()` | 解析 `v`、`person`、`scene`、`display`；保存 `scene` 和最后成功时间 |

| 服务器 | **不改**；v2 已返回 `scene`/`person`/`display` |
| 接线 | **不改**；OLED I2C、5V 直供、风扇、开关都不动 |

## 9. 备选方案与取舍

| 方案 | 显示 | 优点 | 缺点 |
|---|---|---|---|
| **A（推荐）** | 有人 / 无人 / 看不清 | 忠实反映快通道；遮挡不误报 | 三态，稍多一个字 |
| B（二态） | 有人 / 无人 | 最简单 | `occluded` 会误显示“无人” |
| C（完整姿态） | 端正/低头/侧歪/手机/走神/趴桌/无人/看不清 | 信息最多 | 依赖慢通道，可能滞后；字号/布局更挤 |
| D（`display_cn` 直显） | 服务器中文文案 | 不改映射 | 文案长度不可控，可能超宽 |

> 本需求是“是否有人”，选 **A**。以后要显示姿态，再在 A 的第 4 行后面加 `· 低头`，或换 C。

---

## 10. 不建议做的事

1. 不要只用 `person` 布尔值判断“有人/无人”——`occluded` 会误报无人。
2. 不要用 `state` 做实时显示——它可能滞后 45 秒。
3. 不要长时间保留旧“有人”——超时显示“离线”。
4. 不要在 USB 直供、无电池时保留“低电量”黄灯——会误报。
5. 不要让 GPIO1 悬空——ADC 偶发读数可能触发低电逻辑。

---

## 11. 不改动项

- 接线：OLED SCL=41 / SDA=42、VDD=3V3 飞线、5V/GND 母线都不动。
- 风扇：GPIO21 / S8050 / 1N5819 逻辑不动。
- 安静开关：GPIO47 不动。
- 上传周期：10 秒不动。
- 服务器 `/detect`：v2 不改。
- 吹风规则：连续 2 帧不端正 + 60 秒去重不动。
