## 六、顺带修掉的一个真 bug

把 qwen3-vl-plus 设为主后端后，发现**一半请求先打到备用后端**——`VisionPool._pick` 是**轮转**取后端：

```python
be = self.backends[(self._cursor + i) % n]   # 轮转
```

这在"对等负载均衡"下合理，但本项目是**主备语义**，轮转等于把主备优先级抹掉。
已改为按定义顺序取第一个可用后端：

```python
for be in self.backends:
    if be.name in tried or not self.breaker.allow(be.name):
        continue
    return be
```

单测 23 条全过，已上线。

## 八、403 追加诊断（2026-11-01 13:35，用户反馈"qwen3-vl-plus 额度还有"后）

### 证据链

| 时间 | 现象 |
|---|---|
| 13:24–13:26 | **同一个 key** 成功完成了 21~22 次推理（8 个模型，含 qwen3-vl-plus 3/3） |
| 13:26:49 | 线上第一次用 qwen3-vl-plus 判定成功：`backend=primary latency=3.07s` |
| 13:27:24 起 | 主后端全部 403，池子持续退化到 fallback |
| 13:34:57 | 复测：`max_tokens=1` 仍 403（排除"单次成本/额度"因素） |
| 13:35 | **纯文本模型 qwen-plus / qwen3.7-plus / qwen3.8-flash / deepseek-v4.1-flash 同样 403** |
| 13:35 | `GET /models` 仍返回 200 + 184 个模型 |

### 结论

**不是 qwen3-vl-plus 的模型级问题，也不是 key 写错**：

- key 有效：`/models` 认证通过（401 才是 key 错，这里是 403）
- 与请求规模无关：`max_tokens=1` 依旧 403
- 与视觉无关：**纯文本模型也全部 403**
- 与单个模型权限无关：8 个模型（含 4 个纯文本）表现完全一致

`AccessDenied.Unpurchased` 是账号/业务空间级授权拒绝。
最可能的三种原因：

1. **试用额度已用尽** —— 前 21~22 次推理可能就是免费体验额度上限；
2. **业务空间（workspace）不匹配** —— API Key 属于某个子空间，而购买的资源包/额度挂在另一个空间；
3. **模型服务未真正开通** —— 控制台显示"有额度"，但 qwen3-vl-plus 的"开通/购买"状态未生效。

### 建议在控制台核对四项

1. 百炼 Model Studio → 模型广场 → `qwen3-vl-plus` 是否显示"已开通/已购买"；
2. 费用中心 → 资源包/免费额度 → 是否还有剩余、有效期、**归属业务空间**；
3. 这个 API Key 是否属于上述业务空间（子空间 Key 只能访问本空间资源）；
4. 14:00 后再试一次——若额度按小时/按日刷新，会自己恢复。
