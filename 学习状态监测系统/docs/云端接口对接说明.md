# 云端检测接口对接说明 /detect

> 基于**线上实际部署**的探测结果整理（2026-10-02 测）。
> 线上跑的是一套**融合后端**（响应含 `source` / `state` 字段），与仓库 `cloud/app.py` 的旧版输出结构略有差异。

---

## 1. 接口信息

| 项 | 值 |
|----|-----|
| 地址 | `http://YOUR_SERVER_IP:8000/detect` |
| 方法 | `POST` |
| 密钥 | `CHANGE_ME_DEVICE_KEY` |
| 密钥传递方式 | 请求头 `X-Device-Key` |
| 请求体类型 | JPEG 二进制（`Content-Type: image/jpeg`） |

> 所有 `/detect` 请求**必须**携带 `X-Device-Key` 头，否则返回 `401 invalid device key`。

### 兼容性说明

- `GET /detect` 不允许（405 Method Not Allowed，server: uvicorn，allow: POST）——仅可用 POST。
- 健康检查 `GET /health` → `{"status":"ok"}`。

---

## 2. 请求示例（curl）

```bash
curl -X POST http://YOUR_SERVER_IP:8000/detect \
  -H "X-Device-Key: CHANGE_ME_DEVICE_KEY" \
  -H "Content-Type: image/jpeg" \
  --data-binary @frame.jpg
```

---

## 3. 响应字段

线上实际返回的结构（与仓库 `app.py` 不同，多出 `state` / `source`）：

| 字段 | 类型 | 说明 |
|------|------|------|
| `action` | string | `"blow"` 触发风扇 / `"none"` 不触发 |
| `upright` | bool/null | `true` 端正 / `false` 不端正 / `null` 无法判定 |
| `state` | string | `"upright"` / `"slouch"` / `"unknown"` 等姿态状态 |
| `source` | string | `"fast"`（快速路径）/ `"fused"`（融合路径）判定来源 |
| `reason` | string | 判定原因，如 `"cannot_determine"`、`"fast_path_bad"` |

### 实测响应示例

- 无人体 / 无法判定（QVGA 帧）：
  ```json
  {"action":"none","upright":null,"state":"unknown","source":"fused","reason":"cannot_determine"}
  ```
- 识别到低头/侧歪（单帧测试图）：
  ```json
  {"action":"none","upright":false,"state":"slouch","source":"fast","head_height":0.6605,"shoulder_level":0.0729,"reason":"fast_path_bad"}
  ```

> 仓库 `cloud/app.py` 旧版只返回 `{action, upright, head_height, shoulder_level, reason}`，reason 值为 `no_person`。线上已升级为融合/双路径后端。

---

## 4. 与固件的对接

固件 `firmware/main.ino` 的 `uploadAndHandle()` **只解析 `action` 字段**：

```cpp
const char *action = doc["action"] | "none";
if (strcmp(action, "blow") == 0) { enterBlowing(); }
```

因此线上响应新增的 `state` / `source` 字段**不影响固件**，固件已兼容，无需改动解析逻辑，只需更新 `config.h` 中的服务器地址与密钥：

| 配置 | 值 |
|------|-----|
| `SERVER_URL` | `http://YOUR_SERVER_IP:8000/detect` |
| `DEVICE_KEY` | `CHANGE_ME_DEVICE_KEY` |

> 注意：固件 `main.ino` 的 JPEG 响应解析使用 `StaticJsonDocument<256>`，线上响应 JSON 体积约 100+ 字节，小于 256，足以容纳。

---

## 5. 判定逻辑（来自仓库代码）

- 连续 2 帧不端正 → 触发 `blow`（约 20 秒）。
- 触发后 60 秒内去重，不重复触发。
- 恢复端正立即返回 `none`。
- 无人 / 关键点置信度不足 → 视为"无法判定"，不触发（宁漏报不误报）。

---

## 6. 安全与数据

- 请求头校验 `X-Device-Key`，不一致返回 401。
- 云端不落盘、不存库，用完即弃（隐私上云已接受）。
