# 服务器端判断策略（现行，2026-11-09 核对线上代码）

> 依据：`/opt/posture/app.py`、`multimodal.py`、`posture.py` 与线上 `.env` 实际值
> 入口：`POST /detect`，设备约每 10 秒一帧

---

## 一、总览

```
ESP32-S3-CAM ──POST /detect──▶ ① 方向自适应
                                  │
                                  ▼
                            ② 快速通道（本地，~100ms）
                             YOLOv8n-pose → head_height/shoulder_level
                                  │
                    ┌─────────────┴──────────────┐
                    │                            │
          ③ 慢通道（异步，30s 一次）      ④ 融合 fuse()
           11 个后端 / 5 个账号              │
           并行 3 路、双票、15s 截止   ──────┘
                                             │
                                             ▼
                                    ⑤ 规则引擎（吹风判定）
                                             │
                                             ▼
                                    返回 action / upright / state
```

**铁律：模型调用永远不在 `/detect` 请求路径上。** 固件超时 8 秒，模型要 3~40 秒。

---

## 二、① 方向自适应

```python
_flip_hint ∈ {None, True, False}   # 进程级记忆
```

| 情况 | 行为 |
|---|---|
| 已记住"倒装" | 推理前先转 180°，每帧只推理 1 次 |
| 未知/正装 | 先按原方向推理；认不到人 → 转 180° 再推理 |
| 翻转命中 | `_flip_hint = True`，写日志 `auto-rotate: 180° 方向命中，已记住` |

代价：只有第一帧可能需要推理两次。

## 三、② 快速通道（本地 OpenVINO，实测 ~90~110ms）

```
CONF_THRESHOLD = 0.5
```

**a. 人体检测**：得分 < 0.5 → `keypoints = None`（视为画面无人）

**b. 特征提取**（`extract_features`），门槛：

| 检查 | 失败结果 |
|---|---|
| 鼻子、左右肩置信度 ≥ `KP_CONF_THRESHOLD` | `low_kp_conf` |
| 肩宽 ≠ 0 | `bad_shoulder_width` |
| 肩宽 ≥ 图像宽度 × `MIN_SHOULDER_WIDTH_RATIO` | `shoulder_too_narrow` |
| `head_height` ≤ `MAX_HEAD_HEIGHT_RATIO` | `pose_geometry_unreliable` |

计算：

```
shoulder_width = |ls_x − rs_x|
head_height    = ((ls_y + rs_y) / 2 − nose_y) / shoulder_width
shoulder_level = |ls_y − rs_y| / shoulder_width
```

**c. 判定**（`is_upright`）：

| 条件 | 结果 |
|---|---|
| 特征无效 | `None`（无法判定） |
| `head_height < 0.28` | `False`（不端正） |
| `shoulder_level > 0.45` | `False`（极端侧歪） |
| 其余 | `True`（端正） |

> `0.28` 来自真机 120 帧标定：端正最低 0.493、趴下最高 0.080。
> `0.45` 等于把这个特征基本停用（实测无区分度），只留极端侧歪兜底。

## 四、③ 慢通道（异步，绝不阻塞）

**触发节奏**：`should_run()`（最小间隔 `MULTIMODAL_INTERVAL=30s`）+ `_running` 互斥；正在跑就不重复触发。

**多后端池**：

| 配置 | 值 |
|---|---|
| 后端数 | 11 个（5 个账号） |
| `AI_PARALLEL` | true，最多 3 路并发 |
| `AI_QUORUM` | 2（双票一致才采信） |
| `AI_PARALLEL_DEADLINE` | 15 s |
| 单后端超时 | 12 s（primary）/ 10~16 s（fallback） |
| 熔断 | 连续 3 次失败 → 冷却 120 s |
| 选路 | 优先不同 `base_url`（不同账号），再按 EWMA 速度 |
| 坏例 | 落盘 `/var/log/posture/badcase` |

**发给模型的两类线索**（新增）：

| 快通道状态 | 追加给模型的线索 |
|---|---|
| 完全没检出人 | `快速通道未检测到人体关键点。` |
| 检出人但关键点不可靠 | `检测到人体，但头部/肩膀关键点不可靠——可能是低头、趴桌或背对镜头。请优先考虑 sleep 或 slouch，不要因为看不到脸就判 away。` |
| 正常 | 不加 |

第二条是"趴桌必看不到鼻子"的解药（A/B 实测 sleep 识别 2/12 → 9/12）。

**结果缓存**：`MULTIMODAL_TTL=45s`，过期视为没有结果。

## 五、④ 融合（`fuse`，优先级从上到下，命中即返回）

| 序 | 条件 | 输出 `upright` | `source` |
|---|---|---|---|
| **1** | 慢通道 `upright=True` 且 `conf ≥ 0.9` 且 **同场景** | **True** | `slow_override` |
| 2 | 快速通道 `False` | False | `fast` |
| 3 | 慢通道 `False` 且 `should_alert=True` | False | `slow` |
| 4 | 快速通道 `True` | True | `fast` |
| 5 | 慢通道 `False` 但 `should_alert=False`（正常低头看书） | None | `slow` |
| 6 | 慢通道 `True` | True | `slow` |
| 7 | 都没有 | None | `fused` |

**"同场景"判定**（`_same_scene`）：慢通道结果带着它分析那一帧的
`(head_height, shoulder_level)` 指纹，与当前帧比对，任一维度差 > 0.12 视为换了场景；
**任一方缺指纹直接不授权**（防止 40 秒前的"端正"套到当前低头帧）。

这就是"慢通道确定的一帧可以无视快通道"的实现——**但必须同意且置信度 ≥ 0.9**。

## 六、⑤ 规则引擎（唯一决定吹不吹风的地方）

```python
upright is None  → bad_streak = 0, action = none
upright is True  → bad_streak = 0, action = none
upright is False → bad_streak += 1
    若 bad_streak ≥ 2 且距上次吹风 ≥ 60s → action = blow, bad_streak = 0
```

即：**连续 2 帧不端正才吹，60 秒内最多吹一次。**

> 注意：吹风只看 `fused.upright`，不看 `should_alert` 字段。
> `should_alert` 目前只在融合的第 3 步用来筛"慢通道单独定的不端正"。

## 七、几个状态的实际走向

| 场景 | 快通道 | 慢通道 | 融合结果 | 吹风 |
|---|---|---|---|---|
| 正常坐直 | True（hh≈0.52） | 通常 true | True/fast | ❌ |
| 低头伏案 | False（hh<0.28） | 可能 true | 若慢通道 conf≥0.9 且同场景 → **被否决为端正** | ❌ |
| 低头、慢通道说"该提醒" | False | False+alert | False/slow | ✅ 2 帧后 |
| **趴桌 sleep** | **None**（鼻子不可见，几何定义决定） | `sleep`（带线索） | None | ❌ 只记录 |
| 画面没人 | None | `away` | None | ❌ |
| 手挡镜头/全黑 | None | `unknown` | None | ❌ |

---

## 八、当前的已知边界

1. **快通道对趴桌天然失效** —— `head_height` 依赖鼻子，趴下必然算不出。只能靠慢通道。
2. **慢通道是抽查**（30s 一次 + 45s TTL），一次判定最多覆盖 1.5 个抽查周期；
   快速切换姿势时会有滞后，靠帧指纹避免误用。
3. **`shoulder_level` 基本停用**（阈值 0.45），侧歪检测目前只有极端情况下生效。
4. 应答里还没有 `slow_age`（结论新鲜度），只是内部用 TTL 控制。
5. 吹风只看几何特征与融合结果，**不看连续时长之外的其它上下文**（如时段、任务状态）。
