## 二、P0(先改这三条,都是一行级/零风险)

### P0-1 快通道失效的**原因**没有进日志 → 线上无法定位

**证据**
- `posture.py` 定义了 4 种失效原因:`low_kp_conf`(:60)、`bad_shoulder_width`(:66)、
  `shoulder_too_narrow`(:72)、`pose_geometry_unreliable`(:94)。
- 该 `reason` 只写进了返回给设备的 JSON(`app.py:467`: `"reason": fused.reason or features.reason`),
  **服务端日志没有**(`app.py:451-455` 的格式串只到 `action=%s`)。
- 结果:22 帧 `valid=False` 里,分不清是"关键点置信度不够"还是"肩宽退化"还是"几何崩坏"。

**改法**(`deploy/app.py:451`)

```python
    log.info(
        "head_height=%.3f shoulder_level=%.3f valid=%s reason=%s fast=%s fused=%s state=%s source=%s action=%s",
        features.head_height, features.shoulder_level,
        features.valid, features.reason,
        fast_upright, fused.upright, fused.state, fused.source, action,
    )
```

### P0-3 帧指纹类型翻转 → 快通道一失效,慢通道的正确结论就**永远用不上**

**这是本轮最重要的缺陷。**

**证据链**
1. `app.py:437-438`:帧指纹随快通道状态**改变类型**
   ```python
   _fkey = ((features.head_height, features.shoulder_level) if features.valid
            else ("img", stats[3]))
   ```
2. `multimodal.py:279-293`:`_same_scene` 要求两端**同类型**才能比较
   - `:280-281` 缓存是 `("img",…)`、当前是几何 → `return False`
   - `:292-293` 缓存是几何、当前是 `("img",…)` → `return False`
3. 实测日志完全对上:
   ```
   20:53:22  multimodal: state=upright conf=0.90 evidence=头部正直肩膀平行   ← 慢通道判"端正"
   20:53:42  valid=False … state=unknown source=fused action=none          ┐
   20:53:53  valid=False … state=unknown source=fused action=none          ├ 快通道连丢 3 帧
   20:54:03  valid=False … state=unknown source=fused action=none          ┘
   20:54:05  multimodal: state=upright conf=0.95 evidence=头部居中,肩膀水平   ← 慢通道仍判"端正"
   ```
   慢通道明明两次都看清了"头部居中、肩膀水平",融合结果却全是 `unknown / cannot_determine`
   (`multimodal.py:406-409`),因为类型一翻,`trusted` 恒为 `False`。

**后果**:系统**恰好**在最需要慢通道兜底的时候(快通道不可靠),把慢通道关在门外。反过来,
`slow_override`(`:341-350`)也依赖同一个 `_same_scene`,所以 20:53:23/20:53:33 那两次能生效,
恰恰是因为那几帧**快通道是好的**(几何指纹稳定可匹配)。

**改法(建议)**:让慢通道结果**同时携带图像指纹**,类型不一致时退回汉明距离比较。

- `MultimodalResult` 增加字段 `img_hash`
- `run_async/fuse` 调用处把 `("img", stats[3])` 一并传入并落库
- `_same_scene` 改为:优先按可比较的一对(几何↔几何、img↔img);**类型不一致时改用 img 指纹比对**
  (复用 `:282-289` 已有的 256 位汉明距离逻辑,阈值 32)

## 三、P1(影响判定正确性,需小改 + 回测)

### P1-1 快慢通道互相打架 → 会误触发风扇/灯

**证据**
- 20:50:45 慢通道 `state=slouch alert=True conf=0.85 evidence=头部低于肩膀`
  vs 20:50:47 快通道 `head_height=0.372 valid=True state=upright` —— **1 秒内结论相反**。
- 20:54:05 慢通道 `upright conf=0.95` vs 同期快通道连续 3 帧 `valid=False`。

**机制**
- `multimodal.py:341-350`:只要慢通道 `upright is True` 且 `conf >= slow_override_min_conf`(实测 0.9)
  且 `_same_scene` 成立,就**无条件**推翻快通道,`source=slow_override`。
- `:363-364` 已有对称的语义豁免(慢通道说"姿态类"时**不**推翻快通道的几何判断),
  但**反方向没有护栏**:慢通道说"端正"时可以推翻快通道的"不端正"。

**改法(建议,二选一)**
1. 给 override 加护栏:`fast_upright is False` 且**快通道连续 N 帧(N≥3)有效且一致**时,`slow_override` 不生效;
2. 或对称化:`slow.state in POSTURAL_STATES`(低头/侧歪/趴桌等几何能测的类目)时不做 override,
   只允许"手机/走神/离开"这类几何看不见的**语义状态**翻案。

### P1-3 慢通道 TTL 与抽样节奏不匹配 → 结果"刚落地就快过期"

**证据**:`MULTIMODAL_INTERVAL=30`(抽样间隔)、`MULTIMODAL_TTL=45`(结果有效期)、
实测推理**平均 9.55s / 最长 12.45s**。

**推算**:一次抽查从触发到落库约 `30s 间隔 + 10s 推理 = 40s`,而 TTL 只有 45s,
即结果落地后**只剩约 5 秒**还会被 `latest()` 采信(`multimodal.py:311-313`)。
再叠加 `_same_scene` 的过滤,慢通道实际参与融合的窗口极窄。

**改法(建议)**:`MULTIMODAL_TTL` 提到 **120s**;误报风险改由 P1-1 的**语义护栏**控制
(即"姿态类不翻案"的规则),而不是靠短 TTL 兜底 —— 短 TTL 只会让慢通道白跑。

## 四、P2(体验/运维)

### P2-1 `primary demoted` 每 30–60s 刷一次 WARNING

**证据**:`resilience_live.py:765-769`,实测 `real_ewma = 6.68 ~ 8.48s` vs `best_backup = 0.40 ~ 0.53s`。

**澄清(避免误判为 bug)**:这是 P3 的**软降级**设计,行为本身正确 ——
`_should_demote_primary`(`:333-352`)要求四条同时满足才降级,降级后主用仍在 `fill` 里
**继续参与竞争**(`:770-771`),并非被永久剔除;`real_ewma` 也在持续更新
(8.48 → 7.58 → 6.80 → 7.37 → 6.68),**不存在饿死**。

**真问题**:`backends[0]` 这个主用**长期比最快备用慢 15 倍以上**,而且每次调用都刷 WARNING。

**改法(建议)**
1. 既然选型已结束,把 `backends[0]` 换成实测更快的后端(本机日志里 `best_backup` 稳定在 0.4~0.5s);
2. 日志降为 INFO 并**节流**(同一状态每 N 分钟最多一条),别让它淹没有用信息。

```python
@staticmethod
def _hash_same(a, b) -> bool:
    if not a or not b or len(a) != len(b):
        return False
    return sum(bin(x ^ y).count("1") for x, y in zip(a, b)) <= 32

@staticmethod
def _same_scene(cached_key, cur_key, cached_img=None, cur_img=None) -> bool:
    if cached_key is None or cur_key is None:
        return MultimodalDetector._hash_same(cached_img, cur_img)
    if isinstance(cached_key, tuple) and cached_key and cached_key[0] == "img":
        if not (isinstance(cur_key, tuple) and cur_key and cur_key[0] == "img"):
            return MultimodalDetector._hash_same(cached_img, cur_img)   # 类型不一致 → 退回哈希
        ...
    if isinstance(cur_key, tuple) and cur_key and cur_key[0] == "img":
        return MultimodalDetector._hash_same(cached_img, cur_img)       # 类型不一致 → 退回哈希
    ...
```

`app.py` 调用处改为同时传图像指纹:
