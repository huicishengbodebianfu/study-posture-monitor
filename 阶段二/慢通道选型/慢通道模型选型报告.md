## 1. 慢通道到底要模型输出什么（先对齐契约）

读 `cloud/ai_providers.py` + `cloud/multimodal.py` + `cloud/app.py` 后确认的关键事实：

```
ESP32 JPEG ──▶ run_async(每 30s) ──▶ AI-1 看图 → VisualDescription
                                     └▶ AI-2 决策 → BehaviorDecision(state/upright/should_alert)
快速通道 YOLO ──▶ fast_upright ──▶ fuse(fast, slow) ──▶ rule_engine.update(upright)
```

**重点：`fuse()` 只认 `upright` 这一个字段，`should_alert` 在现有代码里不参与触发。**

- `slow.upright == False` → 融合层直接判"不端正" → 连续 2 帧 → 吹风
- 也就是说：**把"端正"误判成 `slouch`，在现有代码下会直接造成误报**；
  反过来"不端正"判成 `upright` 只是漏报（符合 D9 宁漏报不误报，但慢通道就失去了翻案价值）。

这条决定了评分口径：**"端正样本上的 `upright` 误判数"是本次选型的第一指标**，其次才是整体准确率、延迟、成本。

| 百度网盘（pnx2） | 分享链接需登录网盘账号/客户端，脚本无法直取 | ✗（未获取） |

这些数据集都是"**睡意/驾驶员疲劳**"域，且受隐私与授权限制。于是改为：

1. **联网图片检索**（Bing 图片异步接口，10 组中文关键词，抓 100 张候选）；
2. 人工逐张核验，选出 **16 张**与项目场景吻合的（书桌/教室/台灯/多人/空教室/发呆）；
3. **统一缩放到 640 宽**（±1px），因为慢通道真实输入就是 ESP32-CAM 的 VGA 帧——这一步是本次测试"贴近部署"的关键，而不是拿高清图刷分；
4. 再加**项目自己的 8 张实拍帧**（`项目\测试记录\`），覆盖过曝、手挡镜头、天花板视角、全黑帧、QVGA、侧脸仰头这些真实疑难场景。

最终 **24 张**：16 张联网 + 8 张实拍。其中 **18 张为明确真值**，6 张（背影/极暗/侧脸仰头）标注为 `ambiguous`，**不计入严格准确率**——因为人自己也难给出唯一答案，硬算会污染排名。

> 说明：联网素材含商业图库水印，仅用于内部模型评估，不进入交付物、不再分发。

素材清单与真值：`images/test/labels.json`；核对图：`images/test_check.jpg`。

## 3. 测试方法与口径

- **两套提示词**，都用 `temperature=0.1`、`max_tokens=3000`：
  - **S（判定）**：一次调用直接产出 `state / upright / person_count / should_alert / confidence / reason` —— 对应"单模型慢通道"（文档 §8.3 方案 B）。
  - **V（AI-1 视觉描述）**：与 `ai_providers.py` 里 `QwenVLProvider` 的提示词**逐字一致**，产出 `person_present / person_count / scene / posture_hint / object_hint`。
- S 覆盖 **全部 8 个可用多模态模型 × 24 张**（8×24 = 192 次调用）；
  V 覆盖 4 个入围模型 × 24 张（96 次；另有 Sage-A1.5 的 6 条残片因提前终止不计入）。
- 部分模型"推理吃光 token"返回空串，统一用 `max_tokens=8000` 重跑一次并单独记录（`raw_S_fix.jsonl`）。
- 指标：`JSON`（可解析率）、`严格`（state 完全等于真值）、`可接受`（落在 allowed 集合内）、`姿态`（`upright` 布尔一致率）、`端正误判`（真值端正却判 `upright=false`，**即误报**）、`漏判`、`误报alert`、均延迟 / P95、输入输出 token、每千次调用成本。

## 5. 为什么是这几个结论

**① 推理型模型（Agents-A1 / Sage-A1.5 / deepseek-v4.1 / kimi-k2.6）在 3000 token 预算下会"空返回"。**
Agents-A1 在 24 张里有 2 张、V 提示词下有 3 张返回空串，`completion_tokens` 卡在 3000；Sage-A1.5 有 2 张。
慢通道是**每 30 秒无人值守**跑的，一次空返回就是一次静默降级；且它们平均输出 770~1200 token，延迟 15~30 秒。
**sensenova-6.8-flash-lite 平均只输出 284 token，P95 11.4s**，是唯一"轻量且稳"的。

**② 成本差距是数量级的。**
按 30s 一次、每天 4 小时学习 → 480 次/天 → 约 1.4 万次/月/台：

| 模型 | 月成本（单台） |
|---|---|
| sensenova-6.8-flash-lite / intern-s2 / Agents-A1 / Sage-A1.5 | 套餐内 ¥0 |
| qwen3.8-27b | ≈ $41 |
| deepseek-v4.1-flash-1017 | ≈ $57 |
| deepseek-v4-flash-vision | ≈ $59 |
| kimi-k2.6 | ≈ $358 |

文档 §8.4 已经把"慢通道 API 费用超预期"列为风险；这次实测证实**选错模型一个月就是几百美元**。

**③ `deepseek-v4-flash-vision` 命中率最高但必须排除**：`status=deprecated`，**2026-11-22 关停**，替换为 `deepseek-v4.1-flash-1017`。

**④ `qwen3.8-27b` 是最便宜的付费模型，但端正误判 3/6**。它会因为"人低头看书"直接判 slouch——而按 §1 的结论，这在现有 `fuse()` 里就是**直接误报**。

**⑤ Agents-A1 判定最准（`upright` 全对），但 30s 均延迟 / 47.8s P95 超过慢通道周期**，`run_async` 的 `_running` 互斥会让它长时间占着线程、丢弃后续样本；加上 8% 空返回。**适合做"离线复核/疑难复核"，不适合 24/7 在线慢通道。**

## 6. 落地建议

### 6.1 推荐配置（主 + 备，双供应商冗余）

```bash
# /opt/posture/.env
MULTIMODAL_ENABLED=true
MULTIMODAL_INTERVAL=30

# 主：SenseNova（单次调用直接出判定，最省最稳）
AI_PRIMARY_BASE=https://token.sensenova.cn/v1
AI_PRIMARY_KEY=sk-****
AI_PRIMARY_MODEL=sensenova-6.8-flash-lite

# 备：discovery-api intern-s2（同一网关、免计费、0 校正端误判，偏保守）
AI_FALLBACK_BASE=https://discovery-api.intern-ai.org.cn/v1
AI_FALLBACK_KEY=sk-d422****
AI_FALLBACK_MODEL=intern-s2
```

若只允许一个 Key，则：

```bash
AI_PRIMARY_MODEL=intern-s2          # discovery-api 内首选（快、免费、0 端正误判）
# 需要更高召回时：deepseek-v4.1-flash-1017 + MULTIMODAL_INTERVAL=60（26s 均延迟，30s 周期扛不住）
```

### 6.2 必须同步改的代码（否则选型收益会打折）

1. **`fuse()` 尊重 `should_alert`**（当前 `MultimodalResult.should_alert` 被计算但从未使用）。
   实测里 deepseek-v4-flash-vision 对暗光伏案已经写出"属于正常学习动作，不触发提醒"，但 `upright=false` 仍会被融合层翻案。建议：`slow.upright is False and slow.should_alert is False` → 不翻案。
2. **单次调用方案可省掉 AI-2**：sensenova 的 S 提示词已经直出 `state + upright`，用 `MULTIMODAL_INTERVAL=45` 还能再省 1/3 成本；保留 AI-2 的价值在于"跨帧历史"，短期可先并行跑、观察后再切。
3. **失败语义**：现有 `_run()` 在 AI-1 失败时 `return`，不会写入 `_last_result`，旧结果会一直留在缓存里——建议加**结果 TTL**（如 2×interval），过期回退 `None`。
4. **`max_tokens` 提到 2000** 对轻量模型无影响，但若未来换推理型模型必须 ≥ 4000，并显式处理"content 为空但 completion=上限"的截断重试。

### 6.3 不建议

- `qwen3.8-27b`：最便宜，但端正误判 3/6，直接制造误报。
- `kimi-k2.6`：$24.9/千次（≈$358/月/台），且是唯一出现 `should_alert=true` 误报的模型。
- `Sage-A1.5`：端正误判 2 例 + 20% 空返回。
- `deepseek-v4-flash-vision`：**11-22 下线**，不要接入。

## 7. 局限与下一步

1. **样本量**：24 张（18 张严格），其中"端正"只有 6 张。结论方向可信，但**精度估计有 ±15% 量级的不确定度**。建议真机跑 1 周日志做二次确认。
2. **数据域差异**：联网素材是"教室/书桌"通用场景，机位、亮度分布与 ESP32-CAM 装法仍有差距；实拍帧只有 8 张且多为故障帧。**建议按 §6.1 上线后用 `journalctl -u posture | grep multimodal` 收集 200 条真实帧，做一次闭环复评。**
3. **未能拿到带标注的公开睡意数据集**（UL-DD/UTA-RLDD/DROZY 均需申请）。若后续拿到 UL-DD，其 alert/low-vigilant/drowsy/sleepy 四级标签可直接补上"发呆/走神"这一环的真值。
4. **`sensenova` 网关其他模型限流严重**：`glm-5.2`、`deepseek-flash`、`deepseek-v4-flash` 全部 429 `insufficient_quota`，`deepseek-v4.1-flash` 403 不在套餐内，`sensenova-u1.5-lite` 404。该 Key 实际可用的视觉模型只有 `sensenova-6.8-flash-lite` 一个。
