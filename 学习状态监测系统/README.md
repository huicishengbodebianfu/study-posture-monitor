## 1. 这是什么

一个用来"监督自己坐姿"的小装置。它做三件事：

1. **看**：桌上的 ESP32-CAM 每 10 秒拍一张你的照片，传到云端。
2. **判**：云端用 AI 模型（YOLOv8-pose）找出你身体的"关键点"（鼻子、肩膀等），
   再根据这些点的位置判断你是不是**低头、驼背或侧歪**。
3. **提醒**：如果连续两次都判定你坐姿不端正，云端就回一个指令，
   ESP32 收到后让**小风扇对着你吹 5 秒**，同时亮红灯提醒你坐直。

**阶段一只做"坐姿是否端正"这一件事。** 玩手机检测、发呆走神判断、
学习数据统计与每日报告，都放到阶段二及以后。

### 为什么用"风扇吹"而不是"响铃"

- 响铃会打断思路，且容易让人烦躁；
- 风扇吹手是**轻微、物理、不刺耳**的提醒，适合长时间学习场景；
- 配合红色 LED，视觉 + 触觉双重提醒，但都不吵。

## 2. 系统怎么工作

### 2.1 整体架构

```
┌─────────────────┐  每 10 秒一张 JPEG   ┌──────────────────────────────────────┐
│  ESP32-CAM      │ ───────────────────▶ │  云服务器 2C4G (Ubuntu 22.04)         │
│  (OV3660 摄像头) │      HTTP POST       │  FastAPI 收图 → OpenVINO(YOLOv8-pose) │
│                 │                      │  → 规则引擎(连续2帧) → 端正?          │
│  风扇 / 红LED /  │ ◀─────────────────── │  HTTP 响应 JSON {action: blow|none}   │
│  BOOT 免打扰键   │      响应带回指令     └──────────────────────────────────────┘
└────────┬────────┘
         │
   18650(带保护板) + TP4056 + XL3608-5V 电池组 (输出 5V)
```

### 2.2 一次完整的"提醒"流程

```
时间轴（假设你从第 0 秒开始驼背）：

  0s   摄像头拍照 → 上传 → 云端判定"不端正"（第 1 帧）
 10s   摄像头拍照 → 上传 → 云端判定"不端正"（第 2 帧，连续 2 帧达成！）
       └─▶ 云端返回 {"action":"blow"}
       └─▶ ESP32 收到 → 风扇满速吹 5 秒 + 红灯亮
 15s   风扇自动停，红灯灭，回到正常监测
 70s   如果还在驼背，且距上次提醒已过 60 秒 → 再次吹 5 秒
```

**关键点**：从"开始驼背"到"风扇启动"大约需要 **20 秒**（2 帧 × 10 秒）。
这是刻意设计的——避免偶尔动一下就误触发，只有**持续**不端正才提醒。

### 2.3 为什么是"连续 2 帧"

单帧判断容易误报（比如你只是低头捡个笔）。要求**连续两帧都不端正**
（即持续约 20 秒），可以过滤掉绝大多数瞬时动作，让提醒更"可信"。

### 2.4 云端负载有多小

- 上传频率：0.1 帧/秒（10 秒 1 帧）
- 单帧推理：yolov8n-pose 在 CPU 上约 60~150ms
- 服务器 CPU 占用：约 **1%**

也就是说，一台最便宜的 2 核 4G 轻量服务器绰绰有余。

## 4. 快速开始

> 详细步骤见 [docs/部署指南.md](docs/部署指南.md)，这里只给概览。

1. **准备硬件**：ESP32-CAM（带 PSRAM）+ USB-TTL 下载器 + 5V 小风扇 + 红色 LED。
2. **部署云端**：租一台 2C4G 云服务器，上传 `cloud/`，装依赖，导出 OpenVINO 模型，启动服务。
3. **烧录固件**：改 `firmware/config.h` 里的 WiFi 和服务器地址，用 Arduino IDE 上传。
4. **联调标定**：坐直测试不吹，驼背约 20 秒应被吹 5 秒；不准就重新标定阈值。

## 5. 关键设计决策

下表记录了项目里每一个"为什么这么做"的决定，方便日后回顾或修改。

| 编号 | 决策项 | 结论 | 为什么 |
|------|--------|------|--------|
| D1 | 监测对象 | 单人固定用户，无需身份识别 | 自己用，不需要区分是谁 |
| D2 | 摄像头位置 | 桌上正对面平视，距头 0.5~0.6m | 这个距离能拍全上半身，关键点清晰 |
| D3 | 阶段一检测范围 | 仅坐姿端正（低头/驼背 + 侧歪） | 先做最简单可靠的，其他放阶段二 |
| D4 | 上传节奏 | 10 秒 1 帧 | 平衡实时性与流量/功耗 |
| D5 | 触发规则 | 连续 2 帧不端正 → 强风 5s；持续不端正每 60s 重提醒；恢复端正立即停 | 防误报 + 防漏报 |
| D6 | 灵敏度 | 先松后紧（明显不端正才触发），标定后调整 | 初期宁可少吹，避免烦人 |
| D7 | 提醒方式 | 风扇吹手 + 红色 LED + BOOT 键免打扰 5 分钟 | 不吵、可临时关闭 |
| D8 | 供电 | 18650(带保护板) + TP4056 + XL3608-5V DIY；风扇与摄像头共电池，5V 输出并大电容缓冲 | 便携、可充电 |
| D9 | 光照 | 纯环境光；暗光下"检测不到 → 不触发" | 宁漏报不误报 |
| D10 | 云端 | 阿里云/腾讯云轻量 2C4G（约 ¥60-100/月）国内地域；CPU+OpenVINO；HTTP 一问一答 | 便宜、延迟低、无需 GPU |
| D11 | 模型 | 现成 yolov8n-pose.pt，阶段一不微调 | 先用通用模型跑通，微调放阶段二 |
| D12 | 作息 | 无时段判断，开机工作、关机结束 | 简单，不需要定时逻辑 |
| D13 | 开发环境 | 零 Arduino 经验 → 提供可直接编译的完整代码 | 降低上手门槛 |

## 7. 风险与已知限制

| 风险 | 应对 |
|------|------|
| 暗光检测失败 | 已接受（D9），晚上不吹不误报；后期可加 USB 补光 |
| 鼓风机噪声/风压 | 已改 5V 无刷涡轮（静音、定向）；送风距离不足时加导风嘴/软管导流 |
| WiFi 弱/断线 | 固件每周期自动重试；断线期间静默 |
| 画面隐私上云 | 已接受；云端不落盘、不存库，用完即弃 |
| 服务器被乱传 | X-Device-Key 校验（现成）；后续可加 IP 白名单 |
| OV3660 板差异 | 与 OV2640 引脚一致，esp32-camera 库通吃；购买时确认 PSRAM |

## 8. 多态检测（多个 AI API 分开工作）

> **默认关闭**，不影响阶段一验收。这是一个可选的"增强层"，
> 让**多个 AI API 各司其职、分开工作**，与本地 YOLOv8-pose 形成互补。

### 8.1 为什么要多态检测

本地 YOLOv8-pose 是"快速通道"：快（60~150ms）、免费、离线，
但只能看**骨骼姿态**，看不懂"在干什么"。

多态检测是"慢速通道"：慢（秒级）、按量计费、需联网，
但能理解**语义行为**（如玩手机、发呆、低头看屏幕）。

两者**融合**：任一判定不端正即触发提醒，兼顾速度与准确度。

### 8.2 两个 AI 如何分工

| 角色 | 模型 | 职责 | 输入 → 输出 |
|------|------|------|-------------|
| **AI-1 视觉分析** | Qwen-VL（通义千问） | 图像获取 / 看图 | JPEG → 结构化视觉描述 |
| **AI-2 行为决策** | DeepSeek | 行为分析 / 决策 | 视觉描述 → 行为判定 + `action` |

**为什么拆成两个 API？**
- 各司其职：视觉模型擅长"看"，文本模型擅长"推理决策"。
- 可独立替换：换视觉模型不影响决策逻辑，反之亦然。
- 成本可控：慢速通道按 `MULTIMODAL_INTERVAL` 抽查，不必每帧都调。

### 8.3 数据流

```
ESP32 JPEG
   │
   ├──▶ 快速通道：YOLOv8-pose → 特征 → 判定 ─┐
   │                                          ├──▶ 融合 → 规则引擎 → action
   └──▶ 慢速通道：Qwen-VL 看图 → DeepSeek 决策 ┘
              （每 MULTIMODAL_INTERVAL 秒抽查一次，异步不阻塞）
```

### 8.4 如何开启

在 `cloud/.env` 中填入两个 API Key 并打开开关：

```bash
MULTIMODAL_ENABLED=true
QWEN_API_KEY=sk-xxxxxxxx        # 阿里云 DashScope
DEEPSEEK_API_KEY=sk-xxxxxxxx    # DeepSeek 开放平台
MULTIMODAL_INTERVAL=30          # 每 30 秒抽查一次
```

> 详细说明见 [cloud/README.md](cloud/README.md) 第 11 节。

## 9. 阶段二展望

阶段一跑通后，可以逐步扩展：

- **发呆走神检测**：人脸区域裁剪 + Qwen-VL 零样本抽查（每 30~60s 异步询问），
  眨眼/静止规则兜底。
- **学习数据统计与每日报告**：云端记录状态时序 → Qwen 文本模型生成日报。
- **模型微调**：跑通后视精度需要，AutoDL 租卡微调 yolov8n-pose（冻结 backbone，50 epoch）。
- **升级项**：多档风速、WS2812 彩灯、番茄钟联动、HTTP→MQTT 多设备扩展。
