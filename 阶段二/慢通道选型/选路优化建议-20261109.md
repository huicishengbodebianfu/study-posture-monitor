# 慢通道选路优化建议（2026-11-09）

> 依据：近 6 小时 13 轮真实数据 + `resilience.py` 代码
> 现状：延迟中位 **11.95s**、P90 12.30s、max 12.52s；失败 0
> 投票：`vote2/2`×5、`vote3/3`×2、`vote1/1`×3、`vote1/2`×2、`vote1/3`×1
> → **38% 的轮次有后端没在 deadline 前返回**

---

## 先说结论：优先级排序

| 优先级 | 改动 | 预期收益 | 工作量 | 风险 |
|---|---|---|---|---|
| **P0** | 达成 quorum 立即返回（早停） | 中位延迟 **11.95s → 约 7s** | 小（20 行） | 低 |
| **P1** | 账号标识改为"域名 + key 指纹" | 3 路能落在 3 个独立配额上，429 下降 | 小 | 低 |
| **P2** | 每日/每分钟配额计数 | 免费档从"25 分钟耗尽"变成"全天可用" | 中 | 低 |
| **P3** | primary 参与测速 + 软降级 | 慢主用不再拖死整轮 | 小 | **中**（质量） |

---

## P0：达成 quorum 立即返回

### 现状

```python
done, not_done = wait(futs, timeout=self.parallel_deadline)   # 等满 15 秒
```

`wait()` 只在**全部完成或超时**时返回。哪怕两票在 6 秒时就一致了，
只要第三路还在跑，整轮就要拖到 12~15 秒。

### 实测证据

6 小时里 13 轮，中位 11.95s、max 12.52s，**没有一轮低于 6 秒**——
即使 `vote2/2` 说明只需要两票。

### 改法

```python
deadline = t0 + self.parallel_deadline
done_list = []
while time.time() < deadline:
    d, nd = wait(futs, timeout=min(0.5, deadline - time.time()),
                 return_when=FIRST_COMPLETED)
    done_list += [f.result() for f in d if f.done() and not f.exception()]
    valid = [r for r in done_list if r["ok"] and isinstance(r["json"], dict)]
    # 已经够票且同向 → 不等剩下的
    if self._quorum_reached(valid):
        break
```

配合一条**宽限**：达成 quorum 后再等 `150ms`，把"马上也要回来"的那票收进来
（避免刚好多一个不同向的票，投票结果更稳）。

### 风险

- 第三票可能推翻两票一致 → 但 `quorum=2` 本来就是我们定义的"可信"标准，逻辑自洽
- 置信度平均会略微降低 → 用宽限期 + 要求两票 `confidence ≥ 0.8` 缓解

### 预期

中位延迟从约 12s 降到"第二快的返回时间"，估计 **6~8 秒**。
`vote1/1` 那 3 轮（本来就是只回一票）仍会等满 deadline，但那是后端问题，早停救不了。

## P1：账号标识改成"域名 + key 指纹"

### 现状

```python
seen = {primary.base_url}   # 只按域名去重
```

后果：`discovery-api` 下的 6 个 key（A~F，**各自独立配额**）被当成一个账号，
3 路并发里最多只能选到其中 1 个。sensenova 3 个 key、chatanywhere 3 个 key 同理。

**等于 9 个账号被压成 5 个用。**

### 改法

```python
def account_id(be: Backend) -> str:
    # 显式配置优先，否则用 "域名:key指纹"
    return be.account or f"{be.base_url}::{hashlib.sha1(be.api_key.encode()).hexdigest()[:6]}"
```

选路时 `seen` 用 `account_id` 而不是 `base_url`。

### 注意

同一域名的多个 key 往往**共享 IP 级限流**（OpenRouter、discovery 都是）。
所以必须配合 P2 的每分钟限速，否则 3 路打同一个域名更容易 429。

建议组合：**账号分散（P1） + 每账号限速（P2）** 一起上，单上是负优化。

"每 30 秒一轮 × 3 路"的节奏下，**约 25 分钟就会耗尽**，之后只是连续 429 → 熔断 → 再恢复。

### 改法

```python
class QuotaLedger:
    # 两个维度：每日上限 + 每分钟上限
    # 计数器按 account_id 归类
    # 落盘 /var/lib/posture/quota-YYYYMMDD.json（重启不清零，这点很关键）
```

配置：

```

```

选路时：额度耗尽 → 直接跳过，不浪费一次 429。

### 额外好处

`/pool` 能直接展示"每个账号今天用了多少 / 还剩多少"，
不用再靠猜来判断免费档是否还能用。

## P3：primary 参与测速 + 软降级

### 现状

```python
targets = [primary] if primary in avail else []   # 无条件占一个名额
```

且 `seed_speeds()` **跳过 primary**，所以它的 EWMA 一直是 0，
既不能参与比较，也看不出它变慢了。

### 改法（两段式，先测速再降级）

1. 启动时把 primary 也纳入种子测速
2. 选路时做**软降级**：

```python
best = min(rest, key=lambda b: b.latency_ewma or 999)
if primary.latency_ewma and primary.latency_ewma > best.latency_ewma * 1.6:
    # 主用明显慢 → 不占必选名额，改为按速度竞争
    targets = []
```

### 为什么是 1.6 倍而不是"谁快用谁"

primary（sensenova-6.8-flash-lite）是**质量基线**：实测 0 端正误判、94% 可用。
换成"绝对最快"可能换来一个语义判得差的模型，得不偿失。
1.6 倍是"明显更慢"的宽松阈值，只在它真的拖后腿时才降级。

### 风险

这是四项里唯一**可能降低判定质量**的改动，建议 P0~P2 稳定后再做，
并且改完后用 120 帧真机集做一次回归对比。

```
第 1 步：P0 早停                 → 立刻见效，无质量风险
第 2 步：P1 + P2 一起           → 依赖关系，必须同时上
第 3 步：P3 软降级（可选）       → 用真机集回归后再定
```

# P3 实施记录（2026-11-09 16:25）

## 一、先说一个差点踩进去的坑

P3 原本的设计是"primary 比最快备用慢 1.6 倍就降级"。但直接实现会**立刻误降级**：

启动探测用的请求是 **1x1 图 + "只回答ok" + max_tokens=8**，
真实调用是 **638 字符提示词 + 640×480 真图 + max_tokens=800**。两者耗时差了 2~3 倍。

实测（同一次启动探测 vs 真实调用）：

| 后端 | 探测 EWMA | 真实 EWMA | 差距 |
|---|---|---|---|
| primary | 3.04s | 5.34s | 1.8× |
| fallback9 | 2.54s | 7.60s | **3.0×** |
| fallback2 | 2.55s | 7.66s | **3.0×** |

更直接的证据：改版前 primary 探测 2.05s、fallback2 探测 0.36s，比值 **5.7 倍**——
如果拿这个比值判降级，第一轮就会把 primary 踢出保送位，而它其实是质量基线。

### 解法：把两套速度分开记

```python
# Backend 新增
real_ewma: float = 0.0     # 只由真实调用更新
real_samples: int = 0

# _record_latency(..., real=True)
# 启动探测传 real=False，只进 latency_ewma，不进 real_ewma
```

## 二、软降级规则（四条同时满足才降级）

```python
if self.primary_demote_ratio <= 0 or primary not in avail:   return False
if primary.real_samples < 2 or primary.real_ewma <= 0:       return False
healthy = [b for b in rest if b.real_samples >= 2 and b.real_ewma > 0]
if len(healthy) < 2:                                          return False
return primary.real_ewma > self._fastest_real(healthy) * self.primary_demote_ratio
```

- 开关：`AI_PRIMARY_DEMOTE_RATIO`（默认 1.6，`0` = 永远保送）
- **降级是软的**：只取消"必选名额"，primary 仍进入候选池按速度竞争，
  所以它还在被调用、EWMA 持续更新，不会出现"降级后永远测不到"的僵死
